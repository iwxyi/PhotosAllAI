# 通用 Agent 运行时设计

## 目标与边界

Agent 是持续对话和调用应用能力的执行主体。用户先表达目标，Agent 读取上下文、澄清、提出行动、调用工具、观察真实结果，再决定继续或结束。不能把自然语言用关键词映射为固定批处理，也不能用图片顺序假装完成审美筛选。

会话属于 Agent；分析、生成等耗时作业属于现有任务系统。少量图片也可以产生后台作业，但不强制跳转任务中心，不把会话本身包装成任务中心中的批处理。任务中心提供作业状态，侧栏提供目标、过程、确认和结果。

## 执行模型

采用单 Agent、顺序工具调用的观察循环。每轮模型返回一个严格校验的 JSON 行动：`tool`、`ask` 或 `finish`，包含对用户可见的简短说明，不保存或展示内部思维链。工具错误也作为观察回传，允许模型纠正参数或更换方案。条件和循环由每轮观察驱动，不要求用户编写工作流图。流程不是固定的修图流水线：Agent 先理解目标，再动态选择图库、文件夹、文件、表格、任务、配置、视觉和自动化工具；简单操作直接完成，只有异步批量或长时间工作才进入任务状态。

目标可以是修图，也可以是修改表格、移动或批量重命名文件、整理文件夹、导出、配置程序或编程自动化。模型按目标决定需要的证据和确认，不用关键词把所有请求路由到修图流程。规则变更先查询并生成明确预览；高影响写入仍由工具确认。没有安全注册能力时必须报告限制，不能用未注册 Shell 或代码执行伪造完成。混合目标可以按依赖拆成多个分支，等待、失败和部分成功都要持久化并继续观察。

模型读取工具名称、描述、JSON Schema、冻结的图片范围、已执行回执和用户补充。不能调用未注册工具，不能直接运行代码、Shell 或任意网络请求。工具数据和图片分析中的文字均视为数据，不能覆盖系统规则。

首次实现使用现有默认 OpenAI compatible 视觉模型的文本对话能力。调用沿用应用的超时、响应大小限制、鉴权和取消机制；模型配置在设置中维护。没有兼容模型时明确提示，不能退回关键词执行。原生 function calling 可后续通过适配器增加，不改变执行契约。

## 会话与状态

同一会话允许连续目标。每次新目标记录消息和调用账本的边界，历史仍可阅读，但新目标的生成、迭代和审阅必须使用本目标的视觉证据及方案；不能把上一轮方案当作本轮已完成的诊断。`ask` 后的澄清回复继续同一目标，保留证据及累计预算。用户改变待确认行动时，旧确认作废并进入新目标。

等待分为定时等待和作业观察：前者持久化唤醒时间后休眠，后者定期观察任务服务；状态不变时不反复写会话数据库。暂停立即中断等待。非幂等写操作若中断且未返回回执，进程内恢复与重启恢复均先核对实际结果，不能自动重放。外部会话暂停后拒绝新行动，只有显式恢复才可继续；同一 requestId 的查询重试仍返回原回执。

SQLite 保存会话、消息、工具调用、参数、执行状态、真实回执、子任务 ID、唤醒时间和预算。状态为 `idle / running / awaiting_input / awaiting_approval / waiting / paused / completed / failed / canceled`。

新会话冻结当时的图片 ID，后续图库选择变化不改变既有范围。没有图片也允许对话和查询；图片写工具必须显式指定非空图片集合且属于会话范围。扩大范围使用 `scope.request` 展示具体图片并确认，或使用新选择开启新会话。查询可以返回图库信息，但不自动授权修改全库。

暂停中止模型请求并停止发起新工具；已提交的作业继续执行，恢复时读取这些作业，不重复生成。取消会话取消仍活动的关联子任务，但保留已经完成的图片和回执。关闭侧栏不取消会话。重启后运行中会话暂停，用户恢复时继续。已执行但未保存回执的非幂等操作进入人工核对状态，不能自动重放。

模型调用预算按图片数分配（64 + 每张 8 轮，上限 1000），每次用户请求最多 100 个生成输出、单次等待最长 24 小时。达到预算明确停下，用户可继续。历史按字符预算裁剪，同时保留初始目标、最新要求、方案和调用账本，避免无限上下文与遗失目标。等待采用持久化唤醒时间和可取消计时器，不占用任务运行器。

## 工具与确认

初始注册实际支持的应用能力：读取范围内照片/文件夹/模型，读取分析与生成结果，修改评分/收藏/标签，提交单图分析、集合分析、生成作业，查看关联任务，移动文件、移出图库以及等待。每个工具带 Zod 参数、说明、风险和真实结果。更多工作流、导出、设置和插件能力通过相同注册表扩展；未注册功能必须说明限制，不虚构成功。`program.run` 提供受限 JavaScript 文件变换：输入路径必须明确列出且位于已关联文件夹，脚本不能访问网络、密钥、Shell 或未声明路径，代码和时间、读写大小均有上限，写入走确认。它适合 CSV、TSV、JSON 和文本等规则处理；XLSX 等二进制格式仅在运行环境有明确解析器时启用，否则 Agent 应说明限制并选择导出 CSV、应用内工具或请求用户提供可处理格式。

批量扩展名变更使用 `files.rename-pattern.preview` 先返回范围、数量和示例，再由 `files.rename-pattern` 执行。`scope=folder` 只覆盖指定文件夹及子目录，`scope=all-associated` 覆盖所有已关联根目录并始终需要系统确认；执行会复用文件操作历史和 AI 版本路径迁移。为避免把文件伪装成另一种格式，当前只允许 JPEG 家族的 `.jpg` 与 `.jpeg` 互换，其他扩展名变更应由具有明确格式转换能力的工具处理。

评分和标签属于可重放的赋值操作。用户修图目标授权普通分析和生成，Agent 自行选择默认模型、提示词和合理数量，在预算内自动执行。移动和移出图库必须确认具体资源与目标；初始版本不开放永久删除工具。确认绑定服务端保存的调用 ID 和完整参数；修改要求使旧确认失效。拒绝生成一条观察，由 Agent 调整方案或结束。

## 许愿式修图与专业责任

不假设用户是摄影或后期专家。“修好这些图片”已足够启动完整的专业流程，不应追问曝光值、滤镜、修图顺序等普通专业判断。Agent 必须实际逐图检查，按题材优化曝光、白平衡、动态范围、构图、主体层次、肤色、局部光影、干扰和瑕疵，保留人物身份、真实肤质和场景内容。因图制定方案及验收标准，不能用统一滤镜假装专业修图。

Agent 必须有基于内容与表达意图的摄影判断：曝光不是拉平直方图，白平衡不是机械中和色彩。暗调、高调、有意的亮部溢出和深黑阴影都可以是恰当表达；人物肤色明度需结合场景光线决定。按用户要求协调单张表现与组图一致，允许每张曝光和参数不同，以视觉语言、色彩关系、反差和情绪的协调作为整体标准。主动优化实现方式，同时服从用户明确意图。

增加真实多模态 `vision.inspect` 和 `runtime.plan` 工具，强制生成前已有逐图检查和方案，交付前已有生成结果检查。修图开始先读取已有 AI 分析；没有分析时提交分析作业并进入持久化等待，完成后再次读取。分析结果作为结构化诊断依据，但不能替代 `vision.inspect` 的真实像素检查。生成允许指定同图已有 AI 版本作为输入，支持观察问题后继续修正；默认每图三轮优化，受到总轮数和生成预算约束。审美判断由模型基于真实图像完成，不声称拥有确定的客观美学标准；未能达标时明确反馈。只有关键意图歧义、资源缺失或高影响操作需要用户介入。

生成工具先持久化预分配的任务 ID，再按这些 ID 入队。恢复时以 ID 查找作业并补齐尚未入队的部分，不能重复提交。等待子任务时保存调用状态，完成后回传逐项成功和失败结果，不将部分成功描述为全成功。所有写入通过已有服务；图片生成保留原图和版本语义。

## 结构化询问

`ask` 可以附带互斥的 `interaction.choices` 或带标签、占位符和必填标记的 `interaction.inputs`。运行时把它们作为同一条助手消息持久化；侧栏只渲染当前待回答的一组控件，同时保留自由文本输入。选择或提交后仍通过普通用户消息进入同一观察循环，不绕过范围、确认或预算规则。

## 界面

保留侧栏位置和精简风格。显示连续对话、简短工具进度、可展开的调用参数和回执。确认内容始终可见。提供暂停、继续、取消、新会话和历史会话选择。输入在澄清时仍可用；运行时禁止交叉提交。显示冻结范围数量。不要常驻使用说明，不自动导航到任务中心。

## 验证与验收

单元测试覆盖真实观察循环、参数和范围校验、确认与拒绝、澄清、错误回传、预算、暂停取消、持久化恢复、子任务去重、等待、部分失败和模型异常。使用本地模拟模型验证网络适配器和 Electron 会话 UI，不使用真实密钥或付费请求。

运行类型检查、静态检查、全量单元测试、构建、相关 Electron 回归和新增 Agent 端到端测试。检查宽窄侧栏布局、确认可读性、任务中心不自动打开、关闭重开和应用重启恢复。遇到失败修复并重新验证对应风险。记录实际验证结果与尚未支持的工具范围。

## 统一应用能力与开放 MCP

内置 Agent 和外部 Agent 共用一个能力注册表和同一执行运行时。工具直接调用应用服务，不能模拟鼠标点击或复制另一套业务逻辑。工具的参数校验、范围、执行回执、确认、持久化、恢复和子任务去重对两类客户端一致生效。内置 Agent 直接使用注册表；外部通过官方 MCP SDK 的 Streamable HTTP 协议调用，避免进程内执行还需要绕回网络。

外部连接由用户在程序中开启，默认关闭，只监听 127.0.0.1 的随机端口，使用每次开启重新生成的 Bearer token。关闭即撤销连接；不把 token 交给规划模型，不通过工具返回密钥。连接信息显示在程序内，用户可复制到支持 HTTP MCP 的客户端。程序退出即关闭服务，不提供远程公网监听。

外部 Agent 先用 sessions.open 创建持久化外部会话，声明目标与图片 ID 范围，再把 sessionId 传给业务工具。工具调用迅速返回会话状态和调用回执，耗时作业通过 sessions.get 轮询。外部会话不启动内置规划模型，外部 Agent 自己决定下一步。重要操作的确认保留在程序侧栏，外部接口不能自行批准。暂停、恢复和取消与内置会话一致；网络断线不会丢弃已提交作业。每次提交必须带唯一 requestId；重试同一 ID 不重复执行，参数不同则报错。

能力覆盖目录：图库查询、图片与文件夹元数据、标签与智能集合、相册、文件复制/移动/重命名/移出与撤销、文件夹导入/同步/整理、分析与生成、生成版本审阅和回收恢复、流程配置、提示词模板、导出与预设、任务查询及暂停/恢复/取消/重试/排队参数、应用设置与诊断。涉及文件路径变化必须同步生成版本路径和文件夹监听。服务端密钥、任意代码、数据库原始写入、永久清空回收站和自动恢复整个资料库不开放给模型。

会话范围可通过明确的 scope.request 工具申请扩展：展示新图片及数量并由用户确认一次，之后范围内操作自动继续。普通目标不应不断询问用户专业参数。查询不会隐式授权全库写入。全局配置和其他会话任务的控制需要确认；本会话任务的常规控制自动执行。界面保留人工操作入口，Agent 不自动抢占当前页面。

验证增加真实 MCP 客户端的初始化、工具发现、schema、鉴权、会话隔离、重复 requestId、等待作业、确认不可绕过、断线重连和关闭撤销测试。工具覆盖以实际注册清单为准，未提供能力如实说明。

## 外部连接方法

在 Agent 侧栏打开插头按钮，勾选 MCP，复制连接配置并添加到支持 Streamable HTTP 的 MCP 客户端。连接只在此程序运行且开关打开时有效；重新打开会更换端口和令牌。配置中含 Bearer token，应作为凭据处理。程序本身不会把 token 传给内置 Agent 模型。

外部客户端按 `sessions.open`、业务工具、`sessions.get` 的顺序调用。`sessions.open` 的 `assetIds` 是可操作范围，`goal` 是任务目的；业务工具使用 `sessionId`、唯一 UUID `requestId` 和工具自身参数 `input`。返回的 `executing / waiting` 只是进行中，只有调用记录 `done` 和具体回执才代表完成。需要确认时在应用的 Agent 会话列表选择 `MCP` 会话并审阅操作，外部调用不能替用户确认。图片可通过 `photoallisai://sessions/{sessionId}/original/{id}` 或 `/result/{id}` 资源模板按会话范围读取 JPEG 预览。

当前开放的是登记在 `agent-tools.ts`、`agent-app-tools.ts`、`agent-program-tools.ts` 的业务工具以及会话与图片资源接口。窗口布局、系统文件选择器、备份恢复、清空回收站、提供商密钥配置等没有开放为自动工具。Agent 应说明这些能力限制，不能声称已完成。外部连接关闭后，旧 token 和外部会话所有权失效；之前完成的结果仍保留在应用数据库和任务记录中。

模型网络在自动测试中由本地服务模拟，图片、预览、任务、持久化、版本和 UI 链路实际执行。以上证明的是执行与交互契约；没有调用付费模型，不能据此保证真实模型的审美质量、所有自然语言要求的理解能力或每次修图均成功。实际效果仍取决于用户配置的视觉与生成模型。
