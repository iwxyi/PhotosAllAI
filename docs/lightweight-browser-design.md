# 轻量图片浏览器与 AI 任务工具设计提案

> 状态：设计提案，尚未实施。日期：2026-10-24。
> 本文整理本轮产品方向；已有实现与待开发能力在第 12 节区分。旧产品文档中的冲突布局需按本提案确认后统一。

## 1. 产品定位

**打开就能看图，选中就能处理，复杂要求交给 Agent。**

产品以本地图片浏览、整理为第一层，批量处理为第二层，AI 与 Agent 为按需使用的能力。未配置模型时，浏览、搜索文件、整理和本地处理仍应完整可用。

“轻量”同时指操作步骤少、界面负担低、启动与浏览响应快。不能仅靠隐藏按钮达到轻量，也不能要求用户先理解任务系统和模型配置才能看图。

## 2. Picsee 值得借鉴的部分

参考范围为 Picsee 官方网站及公开文档，部分资料发布于 2020–2022 年；没有安装验证其最新客户端。

| 参考能力 | 本程序的设计取舍 |
| --- | --- |
| 直接关联文件夹，不复制图片 | 支持直接打开图片或文件夹，后台索引；用户可再将目录固定到左栏 |
| 完整比例缩略图、多种浏览方式 | 默认完整缩放，提供缩略图大小调整；网格、详情列表、分析视图各有用途 |
| 标签、星级、组合筛选、智能文件夹 | 形成一套整理与查找体系，不再为每个筛选增加独立页面 |
| 双击看图、Esc 返回、同目录切图 | 任意图片列表调用同一个页内看图组件，保留来源状态 |
| 批量重命名、格式转换等工具 | 放入统一“处理”菜单，以参数面板完成，复用任务系统 |
| 多格式、长图、动图浏览 | 按格式实际解码能力逐项支持，区分可管理、可预览、可编辑 |
| 采集、截图、图床、云同步 | 作为后续扩展，不放进首屏，也不作为当前主线前置条件 |

关联目录时保留稳定资源 ID，记录移动与重新关联信息，避免仅按路径识别图片导致历史丢失。

## 3. 信息架构

### 3.1 页面和侧栏的职责

| 区域 | 职责 | 默认呈现 |
| --- | --- | --- |
| 图库 | 浏览、查找、多选、整理 | 启动主页面 |
| 页内看图 | 检查图片、切图、比较版本 | 打开图片时替换中央内容，不新建标签页 |
| AI 批量修图 | 整体与逐图提示词、候选生成、选优 | 使用时打开，保留编辑草稿 |
| 提示词模板 | 模板浏览、示例、创建、管理 | 独立页面，编辑器也可用轻量选择器引用 |
| 任务中心 | 所有批次的进度、结果、错误与历史 | 按需打开；底部提供简要入口 |
| 设置 | 模型、本地缓存、行为、快捷键 | 按需打开 |
| 左侧栏 | 目录、收藏、智能集合与导航 | 可收起，跨页面保持状态 |
| 右侧栏 | AI、Agent、详情三个统一标签 | 同一高度、同一容器，记住用户显示状态 |

Agent 不创建工作区标签页，图片与单批任务不创建详情标签页。搜索默认更新当前图库，只有用户明确保存时才形成智能集合；普通筛选不自动增加标签页。

### 3.2 中央布局

```text
应用栏：工作区标签                                      应用菜单
左栏 | 当前页面工具栏：搜索 / 筛选 / 排序 / 视图 / 更多 | 右栏
目录 |                                               | AI
集合 |                 图片内容                      | Agent
     |                                               | 详情
底栏：左栏开关             后台任务摘要               右栏开关
```

搜索框跟随当前页面的对象：图库搜图片、模板页搜模板、任务中心搜任务。页面内不再重复主标题与介绍。任务统计放入状态标签或任务条，避免额外占一行。

左右侧栏保持全局一致。首次默认以图片内容为主，右侧栏可关闭；之后尊重用户记忆，不随页面强制开合。Tab 隐藏两侧并恢复原组合，输入框中保留正常焦点行为。

## 4. 功能分层：完整但不铺满

| 显示层级 | 放什么 | 规则 |
| --- | --- | --- |
| 常驻 | 搜索、视图、筛选、排序、缩略图大小 | 高频且与当前页面直接相关 |
| 选中后 | 评分、标签、处理、加入队列 | 显示选中数量；合并为稳定的一行操作，不挤占多行 |
| 操作展开后 | 处理参数、模板选择、提示词、详细错误 | 用户发起动作后展示 |
| 右键与更多 | 文件位置、复制路径、批量命名、历史、低频操作 | 按对象和状态变化；必要操作仍有可发现的菜单入口 |
| 设置 | 默认模型、快捷键、缓存、工具栏配置 | 不将服务配置嵌进每个任务表单 |

图标需要工具提示。危险操作使用清楚的文字。不要把所有功能藏进右键，也不要依靠让用户自定义工具栏来弥补默认设计。

## 5. 图库：先看清，再整理

### 5.1 三种视图

- **网格**：默认。固定且可调的缩略图区域，完整显示比例；文件名与星级紧凑呈现。选中、悬停和任务状态不改变卡片尺寸。
- **列表**：文件管理用途。保留小缩略图，列出文件名、尺寸、格式、大小、时间、星级；列可隐藏和排序。表头复选框全选或取消全选，并支持部分选中态。
- **分析**：缩略图加真实分析摘要、问题、标签和建议，长报告展开查看。未分析时显示状态，不伪造建议；无需为每张图常驻一排操作按钮。

先做好稳定网格。自适应行列或瀑布流作为后续可选布局，避免第一阶段引入过多模式。

### 5.2 查找与选择

搜索默认查本地名称、标签、备注等已有数据。筛选在弹层里组合尺寸、格式、星级、颜色、分析状态；生效条件显示为可删除的简短筛选项。语义搜索明确选择，不因普通搜索自动上传图片。

单击选中，Cmd/Ctrl 多选，Shift 范围选择，双击或 Enter 看图。切换视图保留选中范围和定位。输入框里的 Cmd/Ctrl+A、复制粘贴优先作用于输入框，图库快捷键仅在图库焦点范围生效。

“当前焦点图片”与“选中的多张图片”分开：详情显示焦点图片；批量动作使用明确的选中集合。筛选后仍保留隐藏选中项时，操作前明确总数和范围。

### 5.3 文件入口

从系统打开图片、拖入图片或文件夹，即可浏览；打开单图时可切换同目录图片。先显示可用内容，索引和缩略图后台补齐。临时浏览与固定关联目录分开，不要求用户完成导入向导。

文件移动、丢失与重新关联使用稳定 ID；任务保存输入快照与位置。取消关联目录不等于删除历史任务；文件仍存在时可打开，丢失时说明原因并提供重新定位。

## 6. 看图：最大化图片，减少边框与工具

双击后中央区域直接切换到看图，Esc 恢复来源页面的滚动、筛选、多选、展开和编辑状态。图库、任务项、修图原图与候选图复用同一组件，切图范围取自来源列表。

- 文件名、版本与返回入口浮在画布上，无底色；不单占标题栏。
- 底部一行工具条，加一行胶片带；允许隐藏胶片带。
- 默认只显示适应、实际像素、缩放、评分与更多。对比在有可比较版本时出现，播放控件仅在动图等场景出现。
- “适应窗口”显示完整图片；“100%”表示图片像素与显示像素的实际映射，不能把适应倍率称为 100%。高 DPI 下明确统一计算口径。
- 长图支持适应宽度并从顶部浏览；透明图提供透明网格或纯色背景切换。
- 画布不加固定内边距。不同宽高比产生的余白属于正常适应结果，不通过裁切填满。
- 保留右键自定义工具组、排序和弹性空白；窄窗口将低频工具收进更多菜单。

全屏、幻灯片、悬浮参考图作为后续能力，不增加默认常驻按钮。

## 7. 右侧栏：一个容器，三个明确职责

| 标签 | 内容 | 不应重复承载的内容 |
| --- | --- | --- |
| 详情 | 文件属性、EXIF、星级标签、真实分析结果、建议、派生版本 | 生成表单与完整任务队列 |
| AI | 当前选择范围、分析入口与批次概况、加入修图队列、打开批量修图 | 完整分析报告、整体与逐图提示词 |
| Agent | 对话、当前操作范围、步骤摘要、执行结果、展开详情 | 固定步骤向导、第二套任务管理器 |

详情首屏展示图片是什么、主要问题与建议，技术字段分组折叠。AI 多选时按“分析”和“生成”两个区块组织，显示各自数量，避免分析队列与修图队列混成一组。

只保留一层标签栏，切到 Agent 仍使用相同的全高面板。窄窗口可以临时覆盖中央区域显示一个侧栏，关闭后恢复，不把左右栏与中央内容同时压窄。

## 8. 批量处理与 AI 批量修图

### 8.0 流程资产：同一张图的多阶段版本

除了普通的单目录浏览，程序需要支持“流程文件夹”这一种组织方式。它适合把同一张图片的不同处理阶段放在多个子文件夹中，例如：

```text
项目/
├─ 原图/
├─ 后期/
├─ 美颜/
├─ 调色/
└─ AI 修图/
```

这些目录不是五组互不相关的图片，而是一张图片的五个阶段。启用流程聚合后，用户选中“项目”这个外层文件夹，图库按**流程资产**归组：同一来源只显示一张代表图，避免原图、后期、美颜和多个 AI 版本把列表撑满。这是一种显示归组，不执行文件去重或删除。代表图默认选择配置顺序中最后一个存在且可预览的阶段，而非简单选择修改时间最新的文件；同阶段多候选时优先使用用户首选。缺少某个阶段是正常情况，文件离线或匹配冲突才需要提示。

流程聚合以用户配置的规则和磁盘当前状态为依据，不要求预先入库、固定目录结构或本程序生成记录。程序可与 Lightroom、像素蛋糕及其他外部软件协作：它们导出或移动文件后，本程序重新匹配并更新流程视图。资产 ID 用于缓存、任务历史和已知来源追踪，不能成为参与流程的前提，也不能用旧关联覆盖用户当前生效的规则。

### 8.0.1 全局默认与文件夹覆盖

设置中可保存多个流程预设，并选择一个全局常用流程。每个文件夹和相册可选择“继承”“使用其他预设”“自定义”或“关闭聚合”。物理目录默认从最近一个明确设置的父目录继承，再回退到全局默认；相册只在自己的浏览范围使用该相册配置，不修改文件所属目录的规则。

文件夹切换为自定义时，从当前有效规则复制一份，可独立修改；修改全局默认不改变这份副本。界面清楚显示规则来源，并提供恢复继承。第一阶段不逐字段混合继承，避免规则生效情况难以理解。

全局预设是可复用的匹配规则，不是要求所有项目采用同名目录。同一个预设可以匹配“后期”“曝光还原”“LR 输出”等多个实际路径；项目也可以采用完全不同的自定义规则。

### 8.0.2 正则如何匹配阶段与同一张图片

每个步骤至少配置：名称、显示顺序、匹配字段、正则、关联键提取、可选候选版本提取。匹配字段支持相对流程根目录的路径和文件名；内部统一路径分隔符。阶段匹配解决“这是哪个步骤”，关联键解决“它和哪张图属于同一组”，两者不能混为一谈。

例如，以下是可自定义的演示规则，不是强制目录格式：

| 阶段 | 相对路径正则示例 |
| --- | --- |
| 原图 | `^(?:原图|RAW)/(?<key>[^/]+)\.(?:CR3|NEF|ARW|DNG)$` |
| 后期 | `^(?:后期|曝光还原|LR输出)/(?<key>[^/]+?)(?:-曝光)?\.(?:jpg|tif)$` |
| 美颜 | `^(?:美颜|像素蛋糕)/(?<key>[^/]+?)(?:-美颜)?\.(?:jpg|tif)$` |
| 调色 | `^(?:调色|成片)/(?<key>[^/]+?)(?:-调色)?\.(?:jpg|tif)$` |
| AI 修图 | `^AI修图/(?<key>[^/]+?)(?:-AI-(?<variant>\d+))?\.(?:png|jpg)$` |

这些示例显式启用扩展名大小写不敏感。同一 `key` 的文件在当前流程作用域内归组，`variant` 用于区分同阶段候选。文件名完全不同的导出可以使用其他捕获规则或手动映射；不能假定总能自动推断来源。

流程作用域默认是应用配置的项目根目录，相同文件名不能跨项目自动合并。大型父目录包含多个拍摄项目时，可配置项目分组目录或将其捕获为额外的命名空间；组合“项目键 + 图片键”形成归组标识。相册跨多个项目时仍保留该命名空间。

多个规则命中、同阶段多个文件、关联键重复时，不能静默丢弃文件。规则冲突提供匹配预览与明确优先级；同阶段多图保留为候选；无法确定身份的文件独立显示，允许手动关联或排除。用户手动关联作为显式覆盖，可撤销，不混入自动猜测。

配置界面使用紧凑步骤列表，展开单步才编辑正则等高级参数。提供可选的常见预设、即时校验和真实文件匹配预览，显示匹配数、未匹配文件与冲突；保存前能看到哪些文件会归成一组。不将正则编辑器放在日常图库或看图工具栏里。

### 8.0.3 实时适应外部文件变化

监控当前关联目录，文件新增、删除、重命名和移动时增量重算匹配。外部软件写入中的文件先等待稳定再解码；合并短时间重复事件。启动、恢复焦点或监听异常后进行必要校验，并提供手动刷新。

重新匹配更新的是当前视图，不改写文件、不重命名目录、不伪造处理历史。仅凭目录和文件名识别的关系标记为“按规则关联”；只有实际记录过的处理才展示工具、参数和真实父子来源。步骤显示顺序不等于已经证实的执行链，尤其 AI 多个版本应显示为候选分支。

修改规则后保留任务原有输入快照与审计记录；当前流程分组可变化，旧任务不能随之被改写。移动识别存在歧义时不声称 ID 一定连续，保留重新关联能力。

### 8.0.4 在看图中查看整条流程

从流程资产打开看图时，底部胶片带和版本菜单显示阶段轨道，例如：

```text
原图  →  后期  →  美颜  →  调色  →  AI 修图〔候选 1、候选 2〕
```

工具栏提供当前阶段名称、前后阶段切换、阶段筛选和“显示全部版本”。切换阶段只改变查看对象，不改变图库代表项，也不新建标签页。阶段可以按时间或用户定义顺序显示；同一阶段有多个候选时，在该阶段下展开候选组。

看图中应能直接回答三件事：这张图来自哪一个原图、当前看的是哪个阶段、后续还有哪些版本。文件名和阶段名继续使用无底色悬浮文字；版本来源、生成参数和处理时间放入详情侧栏的折叠区域。暂不要求在看图中直接修改流程，先做好可靠的查看和切换。

### 8.0.5 与任务和 AI 的关系

每次处理任务记录输入阶段、输出阶段、工具或模型、提示词和输出位置。AI 批量修图可以把“当前阶段”作为输入，也可以把结果写入新阶段；Agent 可以理解“把调色后的版本再做两组 AI 修图”这类范围，但执行前要展示输入阶段和输出阶段。

流程阶段与普通文件夹需要分开表达：文件夹是物理位置，阶段是图片之间的逻辑关系。用户只想浏览目录时可以关闭流程聚合，回到普通文件列表；切换模式不改变文件。

第一阶段包含全局默认、文件夹覆盖、正则配置与匹配预览、实时归组、看图切换，以及已知来源追踪；均为组织与查看功能。自动执行外部软件、编辑图片和直接在流程轨道上启动处理属于后续增强，不应把这些作为查看功能的前置要求。

### 8.1 普通批量工具

图片“处理”菜单集中提供旋转、缩放、格式转换、压缩、重命名、导出等动作。每个动作打开参数面板，展示输入数量、输出规则和必要预览，确认后生成独立批次。

裁切、水印、元数据移除等需要明确参数和预览的能力逐项接入。相同动作支持保存预设，不为每个动作建立一个新标签页，也不要求用户必须通过 Agent 使用。

### 8.2 AI 批量修图页面

顶部仅保留一个整体提示词卡片，放入模板入口、模型、每图候选数量等紧凑参数；低频的输出目录、格式与高级选项折叠。队列统计、运行与暂停放在列表工具行。没有步骤条和 Agent 输入框。

每个列表项采用：

```text
原图缩略图 + 文件名 / 状态                 单项更多
本图提示词：可折叠编辑，修改后保留简短摘要
候选图 1    候选图 2    候选图 3    ...
```

宽窗口原图在左、提示词与候选在右；窄窗口依次纵向排列。候选使用稳定比例容器，自适应换行。没有候选时不渲染空白候选框和“等待候选”等重复文案；生成中显示真实进度。

整体提示词默认与本图补充组合；提供明确的“补充 / 替换”模式，提交前可查看最终提示词。运行后保存本次参数快照，继续修改草稿不改变已提交任务。

每个原图可以多次生成；候选保留批次、模型、提示词和版本来源，支持设为首选、对比、导出、移除候选。设为首选不自动覆盖或删除其他文件。

右键按对象提供原图位置、生成图位置、重新生成、移出草稿队列等动作；双击原图或候选直接看图。失败信息可展开并一键复制，单项重新生成与整批重试的范围明确。

### 8.3 模板

独立模板页以名称、简短介绍、例图为核心，分类与搜索按需展开。模板编辑保存参数与适用能力，示例图标明是示例。编辑器内的模板选择器仅负责选择和预览，不复制整个市场页面。

## 9. Agent：灵活编排，执行有据可查

Agent 根据用户每次输入动态决定动作，不设置固定业务步骤。界面默认只显示对话、简短步骤摘要和结果；展开后可以看到所用图片、筛选依据、参数、输出文件和错误。

- 输入附近显示可修改的范围，例如“已选 18 张”；没有选择时不能默认为整个图库。用户明确要求全库时才使用全库。
- 执行开始冻结输入集合。用户后续切换目录或多选，不改变正在运行任务的对象。
- 使用与界面相同的操作接口和任务系统，能操作设置、整理、分析、生成、导出；普通界面和 Agent 都能查看同一批结果。
- 能力注册表声明参数、前置条件、权限、撤销方式和实际实现状态。未实现的图片处理不能用改标签代替并声称完成。
- 模糊判断须有证据：相似分组展示相似图片，质量排名展示分析依据；不能用列表前 N 张冒充最佳 N 张。
- 低风险动作直接执行。删除原图、覆盖文件、涉及大量文件的破坏性更改先显示具体范围与影响；尽量采用可恢复方案。
- 遇到接口不支持、模型错误或图片离线，保留已成功结果，解释失败点，允许从失败处继续。
- 偏门要求优先组合已有能力；后续可提供受控扩展工具，限制目录、资源与外部依赖，不能直接给予模型无限制系统操作权。

例：“选最好看的 30 张，打二星，里面 9 张做动漫风”。Agent 应能展开显示评分来源、入选图片、9 张子集、生成参数与输出位置；分析或生成不具备条件时明确停在哪一步。

## 10. 任务：同一份数据，两种密度

一次用户提交形成一个批次，批次有明确类型与独立进度。一个 Agent 请求包含多种处理时使用父操作关联多个子批次，父级只汇总，不重复计数。

底部任务面板与任务中心复用同一分组数据：前者简要，后者详细。都能展开图片项，无需跳到新标签页。

- 批次行：类型、名称、完成数 / 总数、运行状态；展开显示处理中、成功、失败、取消数量。
- 图片项：缩略图、名称、状态与关键结果；点击缩略图或双击图片项打开看图。
- 删除叉和整批重试位于批次行。批量删除放入右键的“清理任务”子菜单，避免重复外部已有按钮。
- 删除任务记录、取消运行、删除生成文件、删除原图是不同动作，名称和影响不能混用。运行批次删除前确认取消与清理范围。
- 错误包含原因、可执行建议、错误码、可复制详情；接口原文经脱敏后展开，不只显示通用失败。
- 自动缩略图缓存等内部工作通常不进入用户任务列表。

## 11. 尺寸与性能

布局按可用内容宽度变化：侧栏设可读最小宽度；中央空间不足时收起低频工具和非必要列，必要时侧栏覆盖显示，不增加第二行标签栏。按钮、名称、候选列表均需验证长文本与系统字体放大。

建议验证 1440、1280、1024、800 像素窗口宽度，以及高 DPI、长中文文件名和大量候选。具体断点根据原型实测决定。

性能设计包括可见区域缩略图加载、网格虚拟化、预取相邻图片、原图按需解码、缓存配额与清理、前台浏览优先、后台任务并发限制。进度优先使用事件更新，避免每个面板各自高频轮询。

验收以冷启动、缓存启动、单图打开、万张目录滚动、后台生成时交互等场景实测。性能目标是待制定和测量的预算，不把未测数字当作已达成保证。

| P1 | 已有模板与模型设置 | 保留独立模板页；任务表单仅选择模型，高级配置进入设置 |

首先修正数据和交互的真实性，再统一信息架构，然后补齐轻量浏览入口和批量处理。每项交付都应同时覆盖普通界面、Agent 调用和任务结果，避免新增三套互不相通的实现。

## 13. 验收场景

1. 未配置 AI 时，打开图片即可看图并切换同目录图片，无导入或配置阻塞。
2. 万张目录可以持续浏览；后台任务不导致输入、滚动和切图明显停顿。
3. 网格、多选、页内看图、Esc 返回保持同一上下文，搜索框支持系统编辑快捷键。
4. 选多张图进入修图草稿，设置整体与本图提示词，各生成多个候选，选优并导出，来源可追溯。
5. 分析结果在分析视图与详情一致；未分析、失败、离线有真实状态。
6. 同时运行分析、生成、导出三批任务，各自有独立进度和可展开图片项；底栏和任务中心一致。
7. Agent 能说明选择了哪些图以及原因，不能把未执行的操作标记为成功。
8. 窄窗口、侧栏开合和切换页面不产生双层标签、越界表单或丢失状态。
