## 1. 文档目的

本文档用于持续定义 PhotoAllIsAI 的产品范围、核心交互、数据结构和技术边界。它是后续原型、接口设计、开发拆分和验收的共同基线。

当前产品聚焦大量本地图片的迅速浏览和图片批任务生成。轻量剪辑是后续相邻能力，网页素材采集不在产品方向内。产品不是 Lightroom 的简单复刻，也不是仅能调用生图接口的壳。其核心定位是：

> 以本地图库为基础，由 AI 完成深度视觉理解、修图决策、生成式编辑和图片语义管理的桌面工作台。

## 2. 产品原则

1. **原图不可变**：任何分析、编辑和生成都不覆盖原始文件。
2. **分析与生成相互独立，但可以串联**：分析结果可以单独使用，也可以转化为生成任务。
3. **结构化数据优先**：AI 可以输出详细文字，但固定参数、问题、对象、标签和生成动作必须同时结构化保存。
4. **批量工作优先**：所有核心能力都应考虑单张、批量、队列和失败恢复。
5. **结果可追溯**：每张生成图都能追溯到原图、分析版本、模板版本、用户要求、模型和最终提示词。
6. **浏览不被后台任务阻塞**：解码、分析、生成、导出使用不同优先级的任务通道。
7. **AI 建议不等于事实**：分析结论包含置信度，人物身份等敏感信息默认不做未经确认的推断。
8. **用户自带模型配置**：程序不内置默认服务商凭据，用户自行配置兼容接口。

## 3. 核心概念

### 3.1 资源、版本与版本组

- **资源（Asset）**：导入图库的一张原始图片。
- **分析版本（Analysis Revision）**：针对某个资源或其派生版本的一次 AI 分析结果。
- **派生版本（Asset Version）**：由 AI 生成、传统处理或导出产生的图片，不覆盖原图。
- **生成批次（Generation Batch）**：一次“生成 N 张”操作创建的任务集合。
- **版本组（Version Group）**：同一原图在相同目标或模板下形成的一组生成结果。

### 3.2 工作区级标签页

支持多标签页，但不采用“一张图片一个标签页”。标签页代表一个完整工作区或功能页面：

- `图库`：目录、相册、智能集合、网格浏览、多选和批量管理组成的资源管理工作区。
- `看图`：可从各类图片列表调用的页内查看模式，提供胶片带、大图、生成版本和快捷比较，不创建标签页。
- `Agent 批处理`：常驻应用 Dock 中、可随时召唤的自然语言操作入口；可以理解当前上下文并代替用户操作整个程序。
- `AI 批量修图`：基于模板、整体提示词和逐图提示词执行可重复批量生成的任务工作区。
- `任务中心`：完整队列、任务历史、失败原因和批量操作。
- `提示词模板`：浏览、创建、编辑和管理模板。
- `搜索`：语义搜索和组合筛选结果，可保留为临时或固定标签页。
- `设置`：模型、缓存、任务、隐私、快捷键等设置。

同一类标签默认只打开一个实例。例如点击设置时，若设置标签已存在则切换过去。图库标签第一版固定为单实例且不可关闭。双击图片在当前页面打开看图，按 Esc 或返回按钮关闭，恢复来源列表的选择、滚动、展开状态及编辑草稿；左右切图以来源列表为范围。菜单或对话框打开时，Esc 优先关闭它们。

标签页需要支持：

左右侧栏可通过底部任务栏最左、最右的箭头分别隐藏或显示，保留宽度和内部状态，并在本机记忆。无修饰键的 Tab 在各工作区及页内看图中同时隐藏两侧，再次按下恢复隐藏前的组合；输入框、编辑区域、菜单及对话框中保留正常的焦点切换。Shift+Tab、Cmd/Ctrl+Tab 保留原有行为。

看图以大图为主：文件名、版本及返回按钮叠加在画布左上角，不单独占一行。对比、缩放、版本、导出和胶片带筛选、排序、视图切换合并到图片下方的一行工具栏，窄窗口允许横向滚动。画布不设置固定内边距，图片保持比例完整适应可用区域；比例不同产生的余白不通过裁切消除。

文件名和版本使用无底色悬浮文字，以轻微阴影保持可读性。工具栏右键打开自定义弹窗，可勾选工具组、上下拖动或用箭头排序、添加及移除弹性空白、恢复默认；布局在本机保存。弹性空白分配剩余宽度，窗口较窄时工具组不压缩换行。图库网格、列表及看图胶片带的缩略图均保持原比例完整显示，悬停不放大裁切。

- 关闭、固定和重新排序。
- 恢复上次会话。
- 未保存编辑状态提示。
- 使用 `Cmd/Ctrl + W` 关闭，`Cmd/Ctrl + Tab` 切换。
- 页面状态保留，例如图库选中项、滚动位置、筛选条件和大图缩放。

## 4. 信息架构

### 4.1 应用框架

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 菜单 / 全局搜索 / 后台状态 / 窗口控制                               │
├─────────────────────────────────────────────────────────────────────┤
│ [图库] [AI 批量修图] [模板] [任务中心] [+]                        │
├──────────────┬──────────────────────────────────┬───────────────────┤
│ 目录与集合    │ 图片列表 / 胶片带                 │ AI / 信息 / 版本   │
│              ├──────────────────────────────────┤                   │
│ 文件夹        │                                  │ 分析结果           │
│ 最近导入      │           大图查看器              │ 生成动作           │
│ 收藏夹        │                                  │ 模板与模型         │
│ 智能集合      │                                  │                   │
│ 标签          │                                  │                   │
├──────────────┴──────────────────────────────────┴───────────────────┤
│ 生成中 1 ｜等待 12 ｜失败 2            暂停全部      展开队列 ︿    │
└─────────────────────────────────────────────────────────────────────┘
```

标签页位于应用工具栏之下。图库、AI 批量修图和模板是独立工作区；看图覆盖当前页面的中央区域，来源页面保持挂载。Agent 批处理不占用标签页，而是常驻 Dock，可在任何标签页中召唤。看图期间侧栏使用当前查看图片的上下文，退出后恢复来源选择。左右 Dock 始终保持；Dock 可以调整宽度、折叠、重排和组合。底部为任务状态条和可展开的任务抽屉。旧会话中的看图标签自动移除，原先激活看图时回到图库。

### 4.2 图库工作区

左栏负责导航，不承担任务编辑：

- 文件系统目录树。
- 最近导入、收藏、未分析、已生成等系统集合。
- 用户相册和智能集合。
- 标签树和常用筛选。
- 回收站仅管理应用派生内容；原图删除需要二次确认并说明影响。

中间区域分为：

- 上部图片网格或横向胶片带。
- 下部大图查看器。
- 图片列表区域可以折叠，以获得更大的查看空间。

图库提供三种可切换视图，视图切换不改变当前选择：列表视图显示缩略图、文件名、评分、尺寸、拍摄时间、分析状态和文件夹；网格视图以缩略图为主要信息；分析视图以缩略图、视觉摘要、质量分数、问题、标签、建议和可执行动作组成高密度列表。分析视图属于图库浏览模式，视觉识别结果直接回写到统一详情 Dock。

右侧统一详情 Dock 采用页签：

- `AI`：分析、用户要求、模板、生成数量和执行按钮。
- `信息`：EXIF、路径、尺寸、评分、标签和 AI 描述。
- `版本`：原图、生成批次、各生成结果及状态。

左右 Dock 固定在应用外壳中，切换标签页时保持显示和顺序。Dock 支持调整宽度、折叠、拖拽重排、组合成标签组，并保存到工作区会话。Agent 批处理位于独立的 Agent Dock 面板中，可通过快捷键、工具栏或详情 Dock 召唤；关闭后恢复原布局。

### 4.3 选择模型与批量交互

图片管理、分析、生成和导出必须共用一致的选择模型，不能在不同页面出现不同的多选规则。

支持以下选择方式：

- 单击选择一项并设置选择锚点。
- `Cmd/Ctrl + 单击` 切换单项选择状态。
- `Shift + 单击` 选择锚点到当前项之间的连续范围。
- 鼠标在空白区域拖动进行框选，滚动到边缘时自动滚动。
- `Cmd/Ctrl + A` 选择当前视图中的项目。
- 使用方向键移动焦点，配合 `Shift` 扩展范围，配合 `Cmd/Ctrl` 保留已有选择。
- 支持“全选当前页/已加载项目”和“选择全部搜索结果”两个不同动作；后者必须显示总数量并二次确认高成本操作。
- 筛选或排序变化后，仍在结果集内的选中项保持选中；不再可见的选中项应在选择摘要中明确提示。

界面始终显示选中数量和当前选择范围。批量操作栏只在多选时出现，并根据资源状态提供：评分、标签、加入相册、移动、复制、分析、生成、导出、从图库移除和移到回收站。

焦点项与选中项是两个概念：焦点项用于键盘导航和大图预览，选中集合决定批量操作范围。任何可能产生费用或改变文件位置的动作，都必须明确显示将影响多少项。

### 4.4 AI 批量修图工作区与共享上下文

AI 批量修图是自由使用的批次工作区，不在页面顶部显示流程导航或 Agent。顶部放置批次整体提示词、模板、模型、生成次数和执行控制；主体是可滚动批量列表。每个列表项聚合一张原图、本次生成的多个候选结果和任务信息，支持抽卡式多次生成、比较候选并选择最佳版本。列表项双击原图或生成图打开看图；右键菜单提供单项重试、重试失败候选、移除本项、加入图库、打开原图位置、打开生成图位置、在 Finder/资源管理器中显示、复制结果路径和导出当前候选。

```text
原图 + 文件名 + 状态 + 单图提示词 + 生成进度
候选 1 · 候选 2 · 候选 3 · 候选 4
最佳版本 / 重试 / 打开看图 / 导出
```

### 4.5 处理工具与共享上下文

Agent 批处理与 AI 批量修图保持逻辑独立，但复用图库与看图的选择能力。Agent 不占用标签页，而是常驻可召唤 Dock；用户可以让 Agent 创建、修改和执行 AI 批量修图批次。图库网格和看图底部胶片带都支持多选、范围选择和当前焦点；选中内容可以通过明确动作加入批次。打开处理工具不会清空图库或看图的选择。

进入处理工具时创建一个不可变的选择上下文快照：

```text
来源：看图胶片带
选中：12 张
焦点：IMG_002.jpg
文件夹：日本旅行
相册：春季旅行
创建时间：刚刚
```

任务默认基于快照执行。用户可以显式点击“同步当前选择”来更新范围，不能因为其他工作区的选择变化而静默改变任务。界面同时区分：

- **输入范围**：快照中的全部资源。
- **最终处理范围**：Agent 或筛选规则实际选中的资源。
- **结果数量**：生成、导出或移动后产生的资源数量。

Agent 批处理默认只展示输入、输出和当前进度；每个已完成步骤可以展开查看具体动作、受影响资源、筛选原因、评分依据和提示词。筛选、排序和去重必须提供可检查的证据，不能只显示“已完成”。用户可以查看被排除资源、恢复单项、替换候选、重做当前步骤或从某一步继续。

操作按风险分级：分析和排序可自动执行；评分、标签、相册关系和生成结果属于可逆操作，执行前显示摘要；删除原图、移动原图、覆盖文件和高成本批量生成必须单独确认。原图删除默认进入回收站，所有步骤、参数和结果都写入任务记录。

#### Agent 执行协议

Agent 是应用级自然语言命令入口，不是单纯的聊天回答器。每个请求都必须生成可审阅的结构化计划，包含输入范围、筛选条件、操作、参数、预期输出和风险等级；执行结果逐步落到任务记录，禁止用静态步骤文本冒充已执行。

- **上下文**：快照当前选择、焦点照片、工作区、图库筛选、活动队列、可用模型和相关设置。用户说“这些照片/当前选择”时使用快照；未选择资源时不得默认为全图库，必须询问范围。
- **图片理解**：模糊、重复、相似度、质量/美学排序、人物/主体/场景等请求必须调用视觉分析或集合分析。返回保留与排除的资源 ID、排序分数、理由和置信度。没有可用视觉模型时报告阻塞，不能模拟判断。
- **图片修改**：提示词可组合全局、模板、分析建议和逐图要求，并显示最终提示词。生成前报告图片数、每图版本数、模型及预计任务数；生成只创建派生版本，不覆盖原图。选择最佳版本写入首选状态。
- **图库操作**：评分、收藏、标签、相册关系、筛选、排序、打开图库/看图/模板/任务/设置、加入或移出 AI 批量队列均通过现有应用命令与服务完成，并回报实际变更数量。
- **设置操作**：只修改明确支持的设置字段；缺少目标值、模型凭据或设置含义不清时先询问。涉及凭据的操作只允许引导至设置界面，Agent 不读取、不回显密钥。
- **风险等级**：读取、分析、导航为低风险；评分、标签、队列、生成和导出为可撤销/可清理操作，执行前简述范围；移动原图、移出图库、系统回收站、删除、覆盖和大批量付费生成属于高影响操作，必须先显示具体资源、目标和数量，再由用户显式确认。
- **确认绑定**：确认令牌绑定计划版本、资源 ID、目标路径和操作参数；确认后若任一项发生变化，计划失效并重新审阅。拒绝确认不产生副作用。
- **可追溯性**：每步记录输入快照、执行参数、受影响 ID、输出、错误和时间；步骤可展开查看证据，可安全重试的步骤支持单步重试。部分失败必须如实列出成功、跳过和失败项目。
- **复杂请求**：拆为依赖图执行，前一步筛选结果作为后续步骤输入；无法可靠解析的数量、评分、目录、风格或筛选标准先提出最小澄清问题，不能静默采用默认值。

首批 Agent 工具接口应覆盖：`catalog.search/list/select`、`analysis.asset/collection`、`metadata.rating/favorite/tags/album`、`workflow.add/remove/configure/run`、`generation.create/review/export`、`files.move/remove/trash/reveal`、`settings.read/update`、`workspace.navigate` 和 `tasks.list/control`。每个工具采用共享 Zod 契约并由主进程再次校验；Renderer 不直接执行文件系统或模型调用。

#### 万能图片 Agent 的扩展架构

“万能”表示可以组合已有能力并在缺少专用按钮时继续完成任务，不表示允许模型直接执行任意代码。Agent 采用受主进程约束的工具运行时，工具按能力注册、按权限执行，模型只负责提出结构化调用和解释结果。

**1. 能力层而不是固定步骤**

固定的 `select/rate/generate` 步骤只能覆盖已知流程。运行时应以工具调用为基本单位，每个工具声明输入 Schema、输出 Schema、风险等级、是否可撤销、是否需要视觉证据、是否需要确认和可用前置条件。工具调用通过 `plan -> validate -> preview -> approve -> execute -> verify` 状态机运行，计划中的每个调用都有稳定 ID、输入快照和输出引用。

首批能力域建议拆成：

- `inspect`：读取尺寸、EXIF、色彩空间、直方图、清晰度、噪声、构图、主体、文字、人物数量、遮挡和相似度。
- `select`：按自然语言条件、分析字段、评分、范围、时间、路径、标签和相似组筛选；支持保留/排除集合和排序证据。
- `transform`：裁切、旋转、翻转、透视、去噪、锐化、曝光、白平衡、曲线、局部蒙版、背景处理、对象移除、扩图、风格化、超分和格式转换。
- `generate`：基于全局/模板/逐图提示词生成多个候选，支持模型、尺寸、种子、负面提示词、参考图和变体关系。
- `evaluate`：对候选按美学、清晰度、身份保持、构图、文本准确性或用户自定义评分，支持多轮生成-评估-淘汰。
- `organize`：评分、收藏、标签、相册、命名、目录、去重、版本、最佳候选和审阅状态。
- `deliver`：导出、复制、移动、共享目录、格式转换、命名规则和报告生成。
- `app`：导航、打开工作区、管理队列、调整设置、查看错误、重试和恢复。
- `custom`：在沙箱内运行受限图像脚本或节点图，只能访问任务输入目录和临时输出目录，不能访问凭据、任意路径或网络。

**2. 不确定需求的澄清和试运行**

偏门要求通常缺少可执行参数，例如“像杂志封面一样”“把最有氛围感的几张处理成一组”“只保留脸没崩的”。Agent 应把目标拆成可检查的判据，优先用低成本分析或 1 张样片试运行，展示样片和判据后再扩展到全批次。无法确定的数量、目录、覆盖策略、身份保持程度、审美偏好或成本上限必须提出最小澄清问题。

支持三种执行模式：

- **预览**：只分析和生成计划，不写元数据、不写文件、不创建付费任务。
- **样片**：对一张或用户指定数量执行，展示输入、参数、输出和评分，用户确认后复制到批次。
- **批量**：锁定样片认可的参数和工具版本，对快照范围执行，可设置最大图片数、最大候选数、最大花费和截止时间。

**3. 视觉证据与结果验证**

每个图片工具都必须返回资源级证据：输入版本、输出版本、区域/蒙版、使用的参数、模型和版本、评分变化、失败原因。生成或变换完成后必须执行验证器，例如尺寸/格式可读性、主体数量、脸部身份相似度、文字 OCR、一致性和文件哈希；验证失败进入重试或人工审阅，不得直接标记成功。

**4. 版本图与可逆编辑**

传统调整和 AI 生成统一为非破坏性版本图。每次修改保存操作节点、父版本、参数和局部蒙版；用户可以比较、分支、回退、把某一步应用到其他照片，或只导出最终合成结果。Agent 不把中间临时文件伪装成最终版本，也不覆盖原图。

**5. 资源预算与并发控制**

计划必须估算任务数、显存/磁盘、网络请求和费用。长任务支持暂停、继续、取消和从失败步骤恢复；同一输入、参数、模型和工具版本产生幂等键，重试不重复计账。批量操作可设置并发、优先级和失败策略（跳过、重试、停止批次、保留成功结果）。

**6. 可观测性和用户信任**

Agent 对用户只突出目标、当前结论和需要决策的地方；步骤可展开查看原始调用、筛选证据、候选差异、失败日志和撤销入口。任何工具都不能声称“已完成”而没有执行回执。模型无法完成时要说明缺少哪项能力、替代方案和预计影响。

**7. 插件和未来扩展**

工具注册表预留 `id/version/provider/capabilities/input/output/risk/permissions` 字段。后续可接入本地 ComfyUI、Photoshop、外部脚本、OCR、分割模型或用户自定义节点，但插件只能通过版本化工具协议访问资源，不得直接依赖 Renderer 状态或内部 SQLite 表结构。

### 4.5 文件夹、相册与文件操作

必须在界面和文案中区分三种容器：

- **关联文件夹**：对真实文件系统目录的路径引用；添加/取消关联本身不移动原文件，但在其中执行移动、复制、重命名或回收操作会直接改变磁盘文件。
- **相册**：数据库中的虚拟集合。加入或移出相册不移动文件。
- **智能集合**：由筛选规则动态生成，不能手工移动资源进入其中。

内置智能集合至少包括最近 30 天、首选照片、未评分、等待 AI 分析、已生成和待审阅。最近集合按 Asset 实际导入时间滚动计算，不能显示演示计数；待审阅集合按生成版本的审阅状态实时计算，便于批量生成后集中处理。智能集合只改变筛选结果，不改变原文件夹或相册关系。侧栏图库摘要必须使用真实文件夹和活动照片数量，不显示推测或硬编码的容量。

用户主动执行文件操作时，程序可以修改原文件，但后台分析和生成绝不能隐式修改原目录。支持：

- 创建、重命名和删除文件夹。
- 在文件夹之间拖动或使用“移动到”命令移动图片。
- 真实文件夹可在关联目录树中拖动到另一目录；移动同步更新 Asset 路径与便携生成版本，禁止自身/后代/同名目标。关联根移入另一关联树后合并索引边界，避免同一路径被重复索引。
- 按住平台约定的修饰键执行复制，并在拖动提示中明确显示“移动”或“复制”。
- 批量重命名，支持原名、序号、拍摄日期等预览变量。
- 从图库移除但保留磁盘文件。
- 移到系统回收站，不提供绕过回收站的默认删除动作。
- 在文件管理器中显示原图或生成结果。
- 文件夹收藏、最近位置和移动目标搜索。

文件操作必须遵循以下可靠性规则：

1. 操作前预检目标权限、可用空间、路径长度、同名冲突和离线状态。
2. 同一磁盘优先使用原子移动；跨磁盘采用“复制、校验、移入源文件回收站”的流程。
3. 文件复制完成后至少校验大小和内容哈希，再更新数据库路径。
4. 遇到冲突时提供跳过、保留两者、替换和统一应用到剩余项目；默认选择保留两者。
5. 操作过程写入持久化日志，应用崩溃后可以判断继续、回滚或人工处理。
6. 可逆的重命名和移动操作进入撤销历史；仅当 Asset 仍位于该操作的结果路径、原路径未被占用且没有活动 AI 任务时允许撤销。关联 RAW/JPEG/XMP 作为同一事务逆序恢复，中断后从持久日志继续；跨卷撤销在写入前重新检查原卷空间。
7. 文件监视器识别由本程序发起的操作，避免把自己的移动误判成文件丢失和重新导入。
8. 外部移动或重命名的文件标记为离线，通过文件指纹、相对路径和内容哈希重新定位。
   当前实现支持文件夹级重新定位：优先按相对路径匹配并保留 Asset ID；改名或目录重组后先以唯一的大小/修改时间指纹保守匹配，再用后台空闲时增量建立的 SHA-256 解析剩余歧义。AI 任务活跃时暂停哈希读取，文件元数据变化会使旧哈希失效；相同内容的重复文件仍保持离线，新文件加入图库。
9. RAW+JPEG、照片+XMP 按同目录与同名主体识别为关联文件组；移动或复制前列出关联文件与额外体积，默认不处理，用户明确勾选后才把它们纳入同一文件事务。RAW/JPEG 继续作为独立 Asset 管理，XMP 不作为照片导入图库。
10. 生成版本与原图的关联依赖稳定资源 ID，原图移动或改名后不需要移动受管生成文件。
11. “取消关联文件夹”只注销该关联根目录并停止监视，不删除、移动或改写目录中的文件。文件夹和其中 Asset 采用软移除，评分、收藏、标签、相册、AI 分析及生成版本继续关联稳定 ID；再次关联同一路径时完整恢复。存在活动 AI 任务或未完成文件事务时必须拒绝操作并说明原因。
12. 文件系统事件允许短时间合并，但协调扫描运行期间到达的新事件必须再执行一轮，不能静默丢弃。监听器断开或根目录暂时不可用时先协调离线状态，再按受控间隔重连；可移动磁盘或网络目录恢复后自动重新扫描。更新导入目录集合时只关闭已移除目录，避免无意义地重建其余监听器。

目录树拖放、网格拖放和菜单移动必须调用同一套文件操作服务，不能各自实现一套不同规则。

### 4.5 导出工作流

应用内生成结果默认由受管图库持久保存。导出是将可交付副本写入用户指定位置，必须足够直接，也要支持专业批量工作流。

导出支持：

- 导出当前版本、每张图片的首选版本、所有接受版本或指定版本。
- 保存并复用导出预设。
- 选择格式、质量、尺寸、色彩空间、元数据和水印。
- 保留原文件名，或使用原名、版本号、拍摄日期、模板名和自定义序号组合命名。
- 保持来源目录结构，或把所有结果汇总到一个目录。
- 同名冲突预览以及跳过、覆盖、自动编号策略。
- 导出前显示文件数量、预计空间和目标目录。
- 导出完成后打开目标目录，并提供成功、跳过和失败清单。

生成版本在交付前可标记为未审阅、已接受、首选或已拒绝。每个资源最多保留一个首选版本；将新版本设为首选时，旧首选自动降级为已接受。审阅状态持久化在生成结果记录中，并可通过待审阅智能集合回溯。
- 将常用导出目录固定到快捷入口。

导出任务已有独立类型、持久化载荷、报告和恢复路径；当前仍与分析、生成、Agent 作业共用顺序执行循环。目标是按资源预算拆分调度，使导出不阻塞浏览和 AI 生成。导出文件不作为新的内部版本自动导入，除非用户明确开启“导出后加入图库”。

### 4.6 视觉设计与动效质量

产品的视觉目标是“安静、精确、具有质感的专业影像工作台”。图片始终是第一视觉主体，界面精致感来自比例、层级、材质、状态和运动的一致性，而不是大量装饰、渐变或悬浮卡片。

#### 视觉方向

- 默认提供适合看图的深色主题，同时支持浅色主题和跟随系统。
- 使用中性背景承托照片，通过有限的功能色表达选择、成功、警告和失败，避免整个界面被单一蓝紫色调主导。
- 建立明确的表面层级：应用背景、侧栏、工具栏、浮层和模态层，每一级对比可辨但不过度割裂。
- 圆角、描边、阴影和模糊都有固定等级；工作区主体保持连续，不把每个区域都包装成卡片。
- 字体层级适合高密度桌面工具，文件名、参数、辅助信息和标题可以快速扫读。
- 使用统一图标库并保持线宽一致；常见操作优先使用图标和工具提示，不重复堆放文字按钮。
- 图片缩略图保持稳定尺寸和比例，评分、状态、AI 标记等叠层不得引起布局跳动。
- 允许紧凑、标准两种界面密度，兼顾笔记本和大屏显示器。

最终颜色、字体和材质需在交互原型阶段通过至少两套视觉方向稿确定，不在需求阶段过早锁定某个流行风格。

#### 动效语言

动效用于解释空间、状态和因果关系，不作为独立表演。建议节奏：

| 类型 | 参考时长 | 用途 |
| --- | --- | --- |
| 即时反馈 | 80–140 ms | 悬停、按下、开关、图标状态 |
| 局部变化 | 160–220 ms | 面板展开、筛选变化、选择反馈 |
| 工作区过渡 | 220–320 ms | 标签页切换、任务抽屉、模板选择器 |
| 直接操控回弹 | 视速度计算 | 拖动排序、分栏调整、比较滑杆 |

动效规则：

- 优先动画 `transform` 和 `opacity`，避免频繁触发布局和大图重绘。
- 弹簧动画仅用于拖动、吸附和直接操控，不让所有元素持续弹跳。
- 标签切换保留空间连续性，但不延迟键盘连续操作。
- 新生成结果到达时使用克制的进入反馈，并保持当前查看位置不被抢走。
- 队列重排清楚展示项目移动和空位变化，取消任务后不突然跳回顶部。
- 图片加载采用低清预览到清晰预览的平滑替换，不能用长时间旋转图标遮住画布。
- 支持系统“减少动态效果”；关闭动画后仍能通过颜色、图标和文字理解状态。

#### 完整状态设计

每个交互组件必须设计并实现：默认、悬停、按下、键盘焦点、选中、禁用、加载、成功、警告、失败和离线状态。重点组件包括：

- 工作区标签栏及未保存状态。
- 目录树、文件拖放目标和移动位置指示器。
- 缩略图单选、多选、焦点和当前大图状态。
- 大图加载、RAW 解码、100% 加载和色彩配置异常。
- 原图/生成图比较控件。
- AI 动作开关、置信度和高风险提示。
- 模板卡片、示例预览和模型兼容状态。
- 任务等待、运行、暂停、重试、失败和完成状态。
- 导出进度、冲突处理和部分成功状态。

空状态和错误状态必须提供下一步操作，但不使用大面积营销式插画占据工作区。

#### 交互细节

- 所有可拖动分隔条都有可见或隐形的足够命中区域，双击可以恢复推荐尺寸。
- 图标按钮有工具提示、键盘焦点和合理的禁用原因。
- 右键菜单、命令面板、顶部菜单和快捷键调用同一命令系统，状态保持一致。
- 高频操作提供即时反馈；耗时操作采用可取消的后台任务。
- 用户切换图片时保留适当的缩放策略，并明确何时沿用上一张的缩放和位置。
- 危险操作通过文案、颜色和影响数量建立层级，不对每个普通动作弹确认框。
- Toast 只报告短暂结果；需要处理的问题进入持久通知或任务中心，不能自动消失。

#### 性能与无障碍预算

- 常规动效以 60 FPS 为目标，动画期间不能启动非必要的大图解码。
- 滚动时暂停低优先级阴影、模糊和非关键动画，优先保证缩略图稳定。
- 避免在大面积区域长期使用高成本背景模糊；Windows 低性能设备提供效果降级。
- 所有核心工作流均可使用键盘完成，并保留清晰焦点环。
- 正文、图标和状态色满足可读性对比要求，不能只用颜色区分任务状态。
- 支持 100%–200% 系统缩放，长文件名、长模型名和中文文本不能覆盖相邻控件。

#### 设计实现与验收方法

AI 可以参与视觉探索、组件实现、动效调参和截图差异修复，但必须遵循固定流程：

1. 先确定设计令牌：颜色、字体、间距、圆角、阴影、图标、层级和运动曲线。
2. 建立独立组件场景，覆盖所有状态和长文本、空数据、大数据等边界条件。
3. 使用真实照片和真实密度数据完成可交互原型，而不是只制作静态效果图。
4. 实现主工作流后，在 macOS 和 Windows 的多种窗口尺寸、DPI 和主题下截图验收。
5. 为关键页面建立视觉回归截图，为拖动、队列、比较和标签切换建立交互测试。
6. 使用性能记录检查掉帧、布局抖动、图片闪烁和内存增长，再进行动画精修。

视觉质量不能只以“接近某张 Dribbble 截图”为验收标准。最终标准是：静态画面精致、真实内容下稳定、高频操作高效、连续使用不疲劳，并且动画不会损害图片加载和批量操作性能。

## 5. 图片浏览与比较

### 5.1 查看模式

大图查看器支持：

- 单图查看。
- 原图与当前生成图一键切换。
- 按住快捷键临时显示原图，松开恢复生成图。
- 左右并排比较，同步缩放和移动。
- 分割滑杆比较。
- 原图、任意生成版本以及两个生成版本之间比较。
- 适应窗口、填充窗口、100% 和自定义缩放。

默认快捷键建议：

| 操作 | 快捷键 |
| --- | --- |
| 按住查看原图 | `O` |
| 原图/当前版本切换 | `\` |
| 左右比较 | `Y` |
| 滑杆比较 | `Shift + Y` |
| 上一个/下一个生成版本 | `[` / `]` |
| 标记首选 | `P` |
| 拒绝当前结果 | `X` |
| 再生成一次 | `Cmd/Ctrl + R` |

快捷键可配置。输入框获得焦点时，单键快捷键不触发。

### 5.2 版本操作

每个生成结果可以：

- 标记首选、接受、拒绝或未决定。
- 与原图或其他版本比较。
- 使用相同参数再生成。
- 修改要求后重新生成。
- 查看完整生成上下文。
- 导出、在文件管理器中显示或删除。

“重试”和“重新生成”必须区分：

- **重试**：面向技术失败，复用相同任务参数，可自动执行有限次数。
- **重新生成**：面向效果不满意，创建新的结果版本并保留旧结果。

批量选择图片后支持每张生成一次或多次，也支持为选中的失败任务批量重试。

## 6. AI 深度视觉分析

### 6.1 分析目标

分析不是一句“这张照片很好看”。一次完整分析需要同时服务四类用途：

1. **照片理解**：描述画面内容、主体、场景、事件和氛围。
2. **质量评估**：识别曝光、白平衡、噪声、模糊、构图和干扰物等问题。
3. **修图决策**：给出可执行的传统参数建议、局部操作和生成式动作。
4. **图库管理**：生成标签、对象、场景和可检索的语义数据。

### 6.2 分析输出层次

#### A. 自然语言报告

允许模型给出详细报告，包括：

- 画面概述和视觉重点。
- 优点、问题及其影响。
- 推荐的修图方向和原因。
- 需要生成式处理的内容。
- 处理风险，例如人脸、文字、商品细节可能被改变。

自然语言报告用于阅读，不直接驱动程序行为。

#### B. 固定调整参数

适用于未来的传统图像处理管线：

- 曝光、对比度、高光、阴影、白色色阶、黑色色阶。
- 色温、色调、饱和度、自然饱和度。
- 清晰度、纹理、去朦胧、锐化、降噪。
- 裁剪比例、旋转和透视建议。
- 局部区域及对应参数。

参数需要包含建议值、允许范围、置信度和原因。第一版可以仅展示并保存，不要求立即实现完整显影引擎。

#### C. AI 专属编辑动作

传统参数无法表达的动作应单独建模，例如：

- 清除背景路人、人群或车辆。
- 清除电线、垃圾桶、反光、污点和其他障碍物。
- 修复被遮挡或缺失的背景。
- 更换或整理杂乱背景。
- 调整局部光照但保持主体身份与材质。
- 扩图、重新构图或补足画面边缘。
- 修复闭眼、穿帮、衣物褶皱等内容问题。
- 保留人物、商品、文字、建筑结构等关键内容。

每个动作必须描述目标、作用区域、期望结果、保护约束、风险和置信度，用户可以逐项启用或关闭。

#### D. 图库语义元数据

- 场景：室内、海边、婚礼、演唱会、城市夜景等。
- 主体：人物、动物、商品、食物、建筑、车辆等。
- 对象列表及大致位置。
- 事件和活动类型。
- 时间、季节、天气、光照和氛围。
- 构图类型、景别和拍摄视角。
- 主色调和风格。
- OCR 文字及语言。
- 自动标签、短描述、长描述和搜索关键词。
- 技术质量评分及可能的重复/相似组。

人物身份、具体地点等结论只有在本地已存在可靠关联时才写入；不能仅凭模型猜测。

### 6.4 分析模式

- `仅分析`：生成报告和元数据，不创建生成任务。
- `分析后确认`：完成分析并预选建议动作，由用户确认后入队。
- `自动分析并生成`：根据自动化规则创建生成任务。

默认使用“分析后确认”。开启全自动模式时，应显示预计图片数、生成次数和潜在调用量。

批量分析应允许用户选择分析深度：

- `快速编目`：描述、场景、对象、标签和基础质量评分。
- `完整修图分析`：包含详细报告、参数和生成式动作。
- `自定义`：由用户选择字段，以控制耗时和成本。

## 7. 分析与生成的联动

分析和生成是两个独立阶段，通过“生成方案”连接：

```text
原图
  ↓
视觉分析 ───────────────→ 图库元数据 / 搜索索引
  ↓
用户审核 AI 建议
  ↓
选择固定调整、生成式动作和提示词模板
  ↓
生成方案预览
  ↓
一个或多个串行生成任务
  ↓
版本组 → 比较 → 接受 / 拒绝 / 再生成
```

最终提示词由以下部分组合：

```text
模型系统约束
+ 原图内容摘要
+ 已启用的生成式动作
+ 模板正文
+ 用户对当前图片或当前批次的补充要求
+ 必须保留的内容
+ 负面约束和风险控制
```

程序必须在入队前展示可编辑的最终提示词。生成任务保存最终文本快照，不能在模板后续修改时被静默改变。

用户可以：

- 单独启用或关闭分析建议中的某个动作。
- 将动作保存为模板的一部分。
- 只使用模板，不使用分析建议。
- 只使用分析生成的动作，不选择模板。
- 在同一原图上创建多套生成方案并分别比较。

## 8. 提示词模板系统

### 8.1 模板内容

模板包括：

- 名称、分类、描述和适用场景。
- 模板正文及变量。
- 展示示例图。
- 可选的模型参考图。
- 支持的模型能力。
- 默认生成次数。
- 内容保护规则。
- 创建时间、修改时间和版本。

建议变量：

```text
{{analysis.summary}}
{{analysis.generative_actions}}
{{catalog.subjects}}
{{user_instruction}}
{{preservation_rules}}
```

展示示例图不能默认发送给模型；模型参考图必须有明确标记。

### 8.2 模板选择器

模板选择器使用大弹层或工作区内抽屉，支持列表和网格视图。卡片展示名称、描述、示例、适用场景、收藏状态和最近使用时间。

支持：

- 搜索、分类和模型能力筛选。
- 收藏、最近使用和自定义模板。
- 预览模板完整说明和更多示例。
- 选中前预览模板将如何与当前分析结果组合。

独立的“提示词模板”标签页用于完整管理。右侧 AI 面板只提供快速选择和最近使用。

## 9. 任务系统

### 9.1 展示方式

采用三级呈现：

1. **底部状态条**：持续显示生成中、等待和失败数量。
2. **底部任务抽屉**：处理当前工作流中的排序、编辑、重试和取消。
3. **任务中心标签页**：查看全部历史、错误详情、调用统计和大规模批量操作。

不把任务队列常驻右侧栏，因为右栏需要保留给当前图片的 AI 操作和版本信息。

### 9.2 任务状态

```text
草稿 → 等待 → 准备输入 → 上传 → 远端处理中 → 下载 → 保存 → 完成
          └──────────────────────────────→ 失败 / 已取消
```

等待任务可以：

- 拖动排序。
- 修改模板、用户要求、模型和生成次数。
- 批量应用修改。
- 暂停、跳过或取消。

运行任务参数锁定。用户修改时可以取消并重新排队，或复制成新任务。程序重启后，等待任务继续保留；中断的运行任务进入“待确认重试”。

生成默认串行执行，并允许用户在设置中为支持并发的服务调整并发数。分析和缩略图任务不与生成任务共用同一个执行槽。

### 9.3 多次生成

“生成 N 次”创建一个生成批次和 N 个独立任务。任务按张串行完成，结果到达后即可查看，不必等待整个批次结束。

等待中的后续任务允许调整：

- 剩余生成次数。
- 最终提示词。
- 模板和模型。
- 顺序和优先级。

修改仅作用于尚未开始的任务，并在界面中明确显示影响范围。

当前版本支持在任务中心统一修改同一照片、同一生成批次内所有等待任务的 Provider、模板版本和最终提示词，并在 1–20 次间增减生成数量。模板重组使用入队时保存的不可变分析版本 ID、动作开关和用户补充要求，避免为每次生成复制整份分析；旧任务缺少该上下文时禁用模板切换。存储策略和已有结果序号仍使用入队快照，避免破坏可追溯性。

## 10. AI 图片管理与检索

### 10.1 检索能力

AI 分析产生的编目数据用于：

- 关键词搜索，例如“海边逆光的单人人像”。
- 条件筛选，例如场景、主体、颜色、质量评分、是否有路人。
- 语义搜索，允许自然语言表达近似含义。
- 智能集合，例如“未处理且背景杂乱的人像”。
- 相似图片和重复图片分组。
- 批量选择同一事件、场景或修图问题的照片。

检索采用混合方案：

1. SQLite 保存结构化字段和全文索引。
2. 向量索引保存描述或图像嵌入，用于语义搜索。
3. 查询层合并文本、结构化筛选和向量相似度。

第一版可先实现结构化筛选和全文搜索，向量检索作为下一阶段能力。数据库必须预留分析模型版本和嵌入版本，便于后续重新索引。

### 10.2 标签治理

AI 自动标签和用户标签分开保存，并记录来源。用户可以确认、编辑或拒绝 AI 标签。相近标签应支持合并或别名，例如“夜景”和“夜晚”。

当分析模型或分析提示词升级时，不直接覆盖已有数据，而是创建新分析版本；用户确认过的人工元数据始终保留。

## 11. 模型与设置

### 11.1 模型配置

至少支持两类可扩展接口：

- OpenAI Compatible：主要用于视觉分析，也可用于支持的图片生成接口。
- NanoBanana Compatible：主要用于图片生成或编辑。

每个配置档包括：

- 名称、接口类型、Base URL、API Key、Model ID。
- 自定义请求头、超时、重试和速率限制。
- 图片输入限制和输出格式。
- 能力声明：视觉、多图、参考图、蒙版、流式输出、异步任务、取消等。
- 连接测试和能力测试结果。

连接测试必须验证模型列表响应，HTTP 200 返回网页、空响应或不兼容数据时不能显示成功；连接成功不等于已验证图片分析能力。视觉分析遇到 HTML 响应时提示检查 API 地址及服务要求的 `/v1` 后缀。同一图片、模型和分析模式的处理中任务复用，生成候选任务保持独立。

模型配置分别指定视觉分析与图片生成的默认项，在服务列表中标记“默认”。同一用途最多一个已启用默认配置；首次配置、禁用或删除默认项时，自动使用该用途首个可用配置。自动分析、批量生成与 Agent 未指定模型时优先使用默认配置；用户显式指定的配置和已创建任务绑定的配置优先，不因切换默认项改变。旧配置自动兼容，不丢失凭据。失败重试继续使用任务原配置，不自动切换服务。

ACE Data Cloud 的专用 Gemini 接口文档使用 `https://api.acedata.cloud/gemini/chat/completions`。若使用平台提供的 `/v1` 兼容入口，应以该入口对目标模型的实际图片分析结果确认兼容性；模型列表连接测试通过不能代替分析或修图能力验证。

ACE Data Cloud Nano Banana 使用独立的 `acedata-nano-banana` 生图接口类型，Base URL 为 `https://api.acedata.cloud`，编辑端点为 `POST /nano-banana/images`。编辑请求发送 `action: edit`、`model`、`prompt` 与 `image_urls`（原图 JPEG data URL），并从 `data[].image_url` 下载生成结果。连接测试只访问模型列表，不执行生图请求；Nano Banana 配置仅用于图片生成。

分析接口返回 HTTP 400、404 或 422 时，从结构化错误中识别明确的模型不可用、JSON 模式不受支持和图片输入不受支持原因，显示对应修复建议；无法识别时保留 HTTP 状态，不将所有参数错误归因为视觉能力。仅存储稳定错误码，不记录服务可能回显的提示词、密钥和路径。模型 ID 必须使用当前服务提供的名称，不假定跨平台别名通用。

ACE 实测兼容记录（2026-10-22）：`/openai/models` 包含 `gpt-6-sol`；使用 `/openai/chat/completions`、该模型、Base64 JPEG 与 `response_format: json_object` 完成整套分析并通过结果 Schema 校验，约 41 秒。JSON 输出要求必须同时写入用户消息，不能只依赖系统消息，避免转接服务报错 “Response input messages must contain the word json”。同账号 `/v1/chat/completions` 的纯文字请求也通过，但不据此推断完整图片分析兼容性。

网络层在最后一次失败响应中最多读取 64 KiB 错误正文供原因分类，不将正文写入任务；超大错误页仍保留 HTTP 状态。HTTP 504 明确提示上游网关超时，不将其误导为密钥或额度问题，也不建议仅延长本地超时。

任务信息分为三个层级：

- AI 侧栏是操作入口。顶部显示当前图片或选择数量；“视觉分析”区提供分析入口与当前图片结果，“批量修图”区显示图片列表数量、添加图片及打开修图页。添加到修图列表只准备素材，不启动后台生成，不称为加入执行队列。
- 底部“后台任务”是执行摘要，只显示运行、排队和暂停的任务以及文件名、范围和执行阶段；失败和已结束的详细记录通过“全部任务与历史”进入任务中心。移除“串行任务”的独立页面暗示。
- 任务中心统一管理执行与完整历史，可筛选全部、进行中、失败和已结束。单图分析每张一项；生成每个候选一项；联合分析和导出明确标注图片或版本数量。任务列表显示实际文件名、单图或多图范围和执行阶段，不将内部阶段估值显示为模型计算百分比。窄窗口优先保留图片、范围、阶段与操作。

API Key 存入 macOS Keychain 或 Windows Credential Manager，不写入普通配置文件和数据库。

### 11.2 设置标签页

设置作为应用级标签页而不是模态弹窗，包含：

- `AI 模型`：统一管理分析和生成服务；服务列表置于表单上方，提供明确的“添加服务”按钮，选中服务后编辑，添加时清空表单并聚焦名称。
- `图片导出`：管理导出格式、尺寸、质量和命名预设。
- `任务与重试`
- `图库、生成文件与缓存`
- `隐私与数据保留`
- `外观与快捷键`
- `诊断与维护`：查看运行摘要、检查图库完整性、复制或导出脱敏诊断。

每个分类只显示对应设置；导出预设和诊断摘要不出现在 AI 模型页面。切换分类时滚动位置回到顶部。

全选命令按当前焦点执行：文本输入框、搜索框和多行输入框选中当前文本；图库网格、列表、分析视图或看图胶片带获得焦点时选中当前已加载的照片。侧边栏和设置导航不触发图片全选。文本输入同时支持 Command+A 和 Ctrl+A；原生菜单全选也遵守相同的焦点规则。

涉及凭据、删除缓存或改变图库位置的操作仍可使用小型确认对话框。

## 12. 性能架构

### 12.1 图像三级管线

| 层级 | 典型尺寸 | 用途 |
| --- | --- | --- |
| 缩略图 | 256–512 px | 目录、网格、胶片带 |
| 屏幕预览 | 2048–4096 px | 普通查看、比较和 AI 交互 |
| 全分辨率 | 原始尺寸 | 100% 查看、生成输入和导出 |

目标管线：RAW 文件优先使用可用的内嵌预览快速显示，按需生成更准确的预览，并对全尺寸查看与处理建立独立解码路径。**当前未实现完整 RAW 显影和经验证的全尺寸 RAW 查看**；现有预览依赖系统解码与可选外部工具，具体格式逐项验收。

### 12.2 客户端边界

```text
Electron Renderer
界面、胶片带视口裁剪、交互、状态展示；图库网格/列表窗口化待做
        │
        ▼
Electron Main
窗口、菜单、SQLite 图库、缓存、任务与模型服务
        │ 未来在真实性能数据支持下抽离重解码与图像计算
        ▼
可选独立图像处理进程（尚未实现）
```

禁止通过 Base64 在进程之间反复传输大图。浏览器层不长期持有全分辨率位图，也不负责最终色彩处理和导出。

### 12.3 调度与缓存

- 当前查看图片加载拥有最高优先级。
- 预取当前图片前后若干张的屏幕预览。
- 快速切图时取消已经过时的解码任务。
- 胶片带已有视口裁剪；图库网格、瀑布流、分组和列表仍需统一窗口化，只渲染视口附近项目。
- 内存和 GPU 纹理使用 LRU 策略。
- 缩略图与预览采用磁盘缓存，可配置上限和清理。
- 缓存默认上限为 5 GiB，可在设置中选择 1、5、10、20 或 50 GiB；修改后立即清理，运行期间生成新预览后延迟复查预算。命中会低频更新最近使用时间，按最久未使用的可重建预览优先清理；清理不得触碰原图、生成结果、分析结果或图库数据库。
- 磁盘缓存键至少包含稳定 Asset ID、源文件修改时间、源文件字节数和预览规格；缓存发布使用同目录临时文件与原子改名，失败和竞争后清理临时载荷。缓存命中、启动恢复和清理只接受普通文件，不跟随符号链接，也不删除未知命名文件。
- 原始文件指纹至少包含路径、大小和修改时间；必要时异步计算内容哈希。
- 当前分析、生成、Agent 与导出作业共用顺序执行循环；目标是按资源类型分配有界并发和前台浏览优先级。缩略图按需请求，仍需统一解码并发与内存预算。

### 12.4 历史目标与验收口径

以下是设计目标，**不是当前实测成绩或发布承诺**。可重复场景、设备矩阵、分位数和当前基线见[性能与稳定性路线图](browsing-batch-generation-roadmap.md)。

- 已缓存缩略图网格滚动目标为 60 FPS。
- 已缓存图片切换无明显等待。
- 冷加载 RAW 时优先在约 300 ms 内展示内嵌预览；该目标需按真实硬件校准。
- 10,000 张资源下，筛选和滚动保持可交互。
- 连续切换大图后内存回落，无持续增长。
- 后台生成或分析不明显影响前台缩放和切图。

### 13.1 原图与生成结果的存储原则

原图目录对后台任务保持只读语义。应用不在原图旁自动创建文件、不改名、不覆盖，也不把生成结果伪装成原图的新修订。只有用户明确执行移动、复制、重命名或删除等文件管理命令时，应用才修改原文件系统。原图与生成结果通过数据库中的稳定 `Asset ID` 关联，而不是仅依赖文件名或路径。

生成结果属于需要长期保存的用户内容，不能放进随时可清理的缓存目录。必须区分：

- **持久数据**：数据库、生成原文件、模板、分析结果和恢复清单。
- **可重建缓存**：缩略图、屏幕预览、临时上传文件和解码中间产物。
- **导出文件**：用户为交付或外部使用主动生成的副本，不由应用自动回收。

### 13.2 存储策略

提供三种明确的存储策略：

#### A. 集中受管图库（默认）

首次创建图库时由用户确认图库位置，默认建议放在系统图片目录下。图库引用原图路径，只把数据库和 AI 派生内容存入受管目录，因此不会改变原文件夹。

```text
PhotoAllIsAI Library/
├── catalog/
│   ├── catalog.sqlite
│   └── backups/
├── generated/
│   └── ab/
│       └── <asset-id>/
│           └── <batch-id>/
│               ├── IMG_1024__ai__v0001__7K3M9Q2A.png
│               ├── IMG_1024__ai__v0002__F4D8N1CX.png
│               └── manifest.json
├── cache/
│   ├── thumbnails/
│   └── previews/
├── temp/
└── trash/
    └── generation/
        └── <result-id>/
            └── <原生成文件名>
```

`ab` 是资源 ID 的短分片，用于避免单个目录包含过多文件。用户不需要手工理解这一结构，应用提供“在文件管理器中显示”。整个图库目录可以由用户备份或迁移。

#### B. 原图旁的 AI 目录（可选便携模式）

需要让生成结果随项目文件夹一起移动时，可以在原图所在目录创建一个固定名称的输出目录：

```text
拍摄项目/
├── IMG_1024.CR3
├── IMG_1025.CR3
└── _PhotoAllIsAI/
    ├── IMG_1024__A81F2C4D/
    │   └── <batch-id>/
    │       ├── IMG_1024__ai__v0001__7K3M9Q2A.png
    │       └── manifest.json
    └── IMG_1025__09BE73A1/
```

资源名后附短 `Asset ID`，用于区分不同目录中导入过、后来又被汇总到同一项目的同名照片。应用扫描图库时必须忽略自己的 `_PhotoAllIsAI` 目录，防止将生成图递归识别成新原图。

该模式只在用户明确选择且目录可写时启用。只读介质、权限不足、云盘占位文件或网络目录写入不可靠时，自动阻止写入并要求改用集中受管图库，不能静默切换位置。

#### C. 用户导出目录

导出用于交付，不等同于内部版本存储。用户可以选择首选版本或多个版本，按命名预设导出到任意目录。导出的文件即使被外部移动或删除，也不影响应用内保存的生成版本。

不建议每次生成完成后同时写入受管图库和原图旁目录，否则容易产生两个内容相同但生命周期不同的副本。每个图库选择一种工作结果存储策略，导出独立处理。

### 13.3 文件命名与版本规则

建议格式：

```text
<原文件名主体>__ai__v<四位递增号>__<结果短ID>.<实际格式>
```

示例：

```text
IMG_1024__ai__v0001__7K3M9Q2A.png
IMG_1024__ai__v0002__F4D8N1CX.jpg
```

规则如下：

- `v0001` 是同一资源下便于用户阅读的单调递增序号。
- 序号通过数据库事务分配，删除旧版本后不复用，也不因排序变化而改名。
- 结果短 ID 来自完整 `Generation Result ID`，用于避免并发生成、复制文件和恢复导入时发生冲突。
- 文件扩展名必须反映实际编码格式，不能照搬 RAW 原图扩展名。
- 原文件名只用于可读性，不能作为数据库主键。
- 写文件前清理平台非法字符，并控制完整路径长度以兼容 Windows。
- 模板名、提示词和日期不默认放进文件名，避免路径过长；它们保存在数据库和清单中，导出时可以作为可选命名变量。

只使用“原名 + 下划线 + 索引”虽然直观，但无法可靠处理同名原图、并发任务、删除后索引复用和跨图库合并。因此采用“可读版本号 + 稳定短 ID”的组合。

### 13.4 恢复清单

每个生成批次保存一个 `manifest.json`，至少记录：

- 完整资源 ID、生成批次 ID 和结果 ID。
- 原图文件名、原路径提示和文件指纹。
- 结果文件名、尺寸、格式和内容校验值。
- 创建时间、模型配置名称和模板版本 ID。
- 数据契约版本。

清单用于数据库损坏后的扫描恢复和跨机器迁移。API Key 永远不写入清单。完整提示词是否写入清单由隐私设置控制；数据库中仍保存任务追溯所需的内容。

### 13.5 完整图库备份

设置页可以把当前图库创建为一个独立目录包。备份过程先生成 SQLite 一致性快照，再根据该快照复制其中引用的集中受管生成结果，并为数据库和每个结果记录文件大小与 SHA-256。全部文件复制和校验完成后才原子发布目录包；中途失败不得留下看似可用的半成品。

```text
PhotoAllIsAI-library-<timestamp>/
├── catalog.sqlite
├── manifest.json
└── generated/
    └── <与受管图库一致的相对路径>
```

备份包不复制原图、系统凭据中的 API Key、预览缓存、临时文件、应用回收站载荷或原图旁便携结果。原图仍由用户自己的存储与备份策略负责；便携结果应随原图项目目录单独备份。需要纳入备份的回收版本必须先在应用内恢复。目标位置必须在当前图库目录之外，避免递归备份和源数据同时损坏。

一致性快照中若存在尚未完成的生成写入意图，备份会同时移除意图和对应的临时结果记录。未完成任务应在当前图库启动恢复后重试，而不能把进程临时路径或尚未形成完整 manifest 的载荷迁入备份。

当前版本已实现备份创建、独立验证和应用内恢复。恢复分为两阶段：运行中先验证并把清单白名单文件暂存到应用数据卷；重启后、任何业务数据库连接建立前再次验证，重写集中受管结果路径，再原子切换图库目录。旧图库保留为带时间戳的恢复前副本，切换失败则继续使用原图库。备份不包含原图，因此跨机器恢复后仍可能需要重新定位原图文件夹；便携结果也需随原图项目单独恢复。即使“成功创建备份包”，也应定期执行独立验证。

### 13.6 写入、删除与迁移

- 下载结果先写入同一目标文件系统内的临时文件，完成格式检查和校验后原子改名。
- 数据库只在正式文件落盘后将结果标记为完成；启动时清理或恢复未提交的临时文件。
- “拒绝结果”只改变状态，不立即删除文件。
- 用户删除生成结果时先移动到图库内部回收站；数据库保留原目标、版本和生成上下文，活动版本、导出、智能集合、批次清单及完整备份均排除回收项。
- 恢复生成结果前必须检查目标冲突且不得覆盖；同卷原子移动，跨卷排他复制并核对大小和 SHA-256 后才删除源文件。删除后版本序号不得复用。
- 设置页显示回收版本数量、实际占用、缺失文件和异常路径数量。永久清理必须二次确认，只允许删除路径严格匹配 `<library>/trash/generation/<result-id>/<file-name>` 的普通文件；符号链接、目录与越界路径跳过并报告，绝不尝试“修正”后删除。
- 永久清理按“数据库登记清理意图、回收目录内确定性隔离改名、删除文件、删除数据库记录”执行。启动和再次清理都会幂等恢复中断状态；原文件与隔离文件同时存在时视为冲突并全部保留，未知文件、多个候选、符号链接和越界路径不做猜测。无清理意图的外部缺失文件只在用户再次确认清理时移除记录，启动过程不自动改变它；单项失败不阻断其他项。
- 诊断页可执行只读存储完整性检查：验证 SQLite `quick_check`，对账活动与回收生成记录，识别文件缺失、路径逃逸、符号链接或目录伪装、不可访问项，以及受管目录中未被数据库引用的载荷。诊断结果只包含健康等级和计数，不返回文件名或路径。该检查不读取并哈希全部图片内容；字节级校验由完整图库备份验证承担。
- 诊断同时对账生成写入意图。正在进行且路径有效的受管临时/最终载荷属于已追踪内容，不计为孤立；意图超过五分钟视为需关注，路径无法按当前 Asset、批次和存储策略验证时视为错误。界面和导出仍只显示计数，不暴露路径、文件名或提示词。
- 清理缓存不得删除生成结果、分析结果或数据库。
- 移动集中受管图库时使用内置迁移流程，暂停任务、校验空间、复制并校验后再切换路径。
- 原图改名或移动后通过文件指纹和内容哈希辅助重新关联，生成结果无需随之改名。
- 便携模式中的整个项目目录被移动后，应根据相对位置和清单重新关联。

## 14. 隐私、成本与可靠性

- 首次向远端发送图片前明确说明将上传的内容。
- 可选择仅发送缩小图、完整图或指定区域。
- 记录每个任务使用的服务配置和调用时间，但日志不得包含 API Key。
- 如果服务能返回用量，则展示实际用量；否则展示任务数和估算标记，不伪造精确费用。
- 技术错误采用指数退避和有限自动重试。
- 内容不满意不自动无限重生成。
- 任务下载完成后先写临时文件，校验成功再原子移动为正式结果。
- 数据库定期备份，并对迁移做版本控制。

## 16. 历史分阶段实施建议

以下为原始阶段划分。当前已跨阶段交付部分能力，后续实施顺序以[路线图](browsing-batch-generation-roadmap.md)为准。

### 阶段 0：交互原型

先完成视觉方向探索和设计令牌，再验证主界面、工作区标签、图片选择、文件拖放、AI 面板、模板选择、版本比较和底部任务抽屉。使用包含长文件名、大量任务和多种比例照片的真实密度模拟数据，不接真实模型。原型必须包含主要动效和完整组件状态，不能只交付静态页面。

### 阶段 1：图库骨架

实现文件扫描、SQLite、缩略图、屏幕预览、RAW 快速预览、虚拟列表和基础元数据。

### 阶段 2：AI 分析与检索

实现分析适配器、统一数据契约、分析版本、AI 标签、结构化筛选和全文搜索。

### 阶段 3：生成与队列

实现生成适配器、生成方案、模板系统、持久化串行队列、多次生成、失败恢复和版本管理。

### 阶段 4：比较与批量工作流

完善同步缩放、滑杆比较、首选/拒绝、批量重试、队列批量编辑和导出。

### 阶段 5：专业化与优化

基于真实相机样本完善色彩、RAW、缓存、GPU 预览、语义检索和更多模型能力。

## 17. 待决策问题

以下问题保留到原型或技术验证阶段决定：

1. 图库是单一全局库，还是允许创建多个完全隔离的图库。
2. 图库标签是否允许同时打开多个项目或筛选上下文。
3. RAW 第一版支持的相机和格式范围。
4. OpenAI Compatible 图片生成是否与 NanoBanana Compatible 共用统一设置入口。
5. 模型响应是否强制 JSON Schema，或允许文本响应后做二次结构化。
6. 生成输入默认使用屏幕级代理图还是完整分辨率转换图。
7. 第一版是否同时开放原图旁便携模式，还是先只实现集中受管图库和手动导出。
8. AI 自动标签的默认词表、语言和同义词策略。
9. 是否在第一版加入图像向量嵌入，还是只索引 AI 文本描述。
10. 固定调整参数第一版只展示，还是实现一组最小可执行调整。

## 18. 验收主流程

第一版的核心闭环应满足：

1. 用户添加一个包含普通图片和 RAW 的文件夹。
2. 程序快速显示缩略图并可流畅切换大图。
3. 用户批量选择图片并执行完整 AI 分析。
4. 程序展示详细报告、参数建议、生成式动作、描述和标签。
5. 用户关闭某些动作，选择提示词模板并补充要求。
6. 用户为每张图片安排多次生成，并在等待队列中调整顺序和参数。
7. 结果陆续出现，用户无需等待全部完成即可查看。
8. 用户按住快捷键查看原图，或使用左右/滑杆模式比较。
9. 用户标记首选、拒绝不满意结果，并对选中图片批量重新生成。
10. 用户通过场景、对象、问题、标签或描述重新找到这些照片并导出首选结果。

## 19. 新用户快速路径与高级路径

当前能力较多，但首次使用不应要求用户理解“相册分析、优化建议、提示词模板、生成批次”等概念。界面采用双层路径：默认提供一条可完成工作的快速路径，专业能力在用户主动展开后出现。

### 19.1 快速路径

快速路径固定为三个动作：

1. **选照片**：在图库或看图中选择一张或多张照片。
2. **选择操作**：右侧 AI 面板分为视觉分析和批量修图。分析直接处理选中的图片；修图先将图片添加到批量修图列表，在修图页设置提示词并开始生成。
3. **查看结果**：分析结果在当前图片的 AI 面板中查看；生成候选在批量修图列表中比较、重试或导出。

分析与生成属于后台阶段，底部任务栏显示当前执行摘要，任务中心提供完整记录和错误详情。添加图片到修图列表是素材准备，不计入后台任务。

### 19.2 批量处理

当选择超过一张照片时，视觉分析按钮显示“分析选中的 N 张”，修图按钮显示“添加选中的 N 张到批量修图”。批量修图页管理整体提示词、逐图提示词及生成候选；任务中心管理执行记录、暂停和重试。每张图片的分析与每个生成候选分别计为一项，联合分析则明确显示图片数量。

### 19.3 Agent 批处理

Agent 批处理是侧边栏中的独立工作区，不要求用户理解中间步骤。页面以输入范围、自然语言输入框和输出结果为主：

1. 显示来自图库或看图的选择快照；没有快照时允许用户选择当前文件夹、相册或搜索结果。
2. 用户输入目标，例如“处理选中图片，删除模糊图，给最好看的照片加上精选标签并导出”。
3. Agent 自动组合分析、筛选、评分、标签、相册、修图、移动、复制、重命名和导出等能力。
4. 默认只显示“分析中、执行中、整理结果”等简洁状态；每一步都可以展开查看具体做了什么以及为什么选择这些图片。
5. 输出页显示输入范围、最终处理范围、结果数量、失败项和目标位置。

Agent 需要把当前上下文作为任务输入，包括来源工作区、资源 ID、选择数量、焦点资源、文件夹/相册、筛选条件和创建时间。用户输入“处理选中图片”时，不需要重复说明资源范围。

Agent 的步骤是可暂停、可重做和可从中间继续的任务节点。分析、搜索和排序可自动执行；评分、标签和生成在摘要确认后执行；删除、移动、覆盖和高成本生成必须单独确认。

### 19.4 AI 批量修图

AI 批量修图是独立标签页中的自由批次工作区。用户加入照片、填写批次和逐图提示词后即可生成；视觉分析为可选辅助，不是生成前置条件，不因尚未分析而静默跳过图片。逐图要求补充批次要求，使用模板时保存版本快照。

点击“生成全部”立即显示提交反馈，同次提交形成一个批次。页面就地显示本批成功版本数／总版本数，以及生成中、排队、暂停、失败和取消数量。进度条按已结束版本数推进，不将未知的模型耗时伪装成精确进度。批次完整成员由任务批次接口读取，切换标签页或重载后恢复，不依赖底部任务栏的分页范围。

每张原图聚合自己的提示词、生成数量、实际任务阶段、完成数和多个候选。等待生成、准备、上传、模型生成、下载、保存、完成、失败与取消均以生成任务为准；视觉分析状态不替代生图状态。失败项显示可读原因、错误码和复制诊断入口，可仅重试失败版本，保留成功候选。生成中阻止重复提交；历史候选继续可看。

页面不再展示历史的分析、优化、提示词等固定流程阶段和额外审阅卡片。任务中心保留跨批次的管理能力。

### 19.5 提示词模板市场

提示词模板是独立的大标签页，使用类似图片选图和网络模板市场的网格体验。模板卡片展示名称、介绍、示例图、分类、标签、收藏状态、使用次数和更新时间；详情页展示完整提示词、负面提示词、变量、适用模型、示例输入输出和版本。

模板来源分为官方、用户和导入模板。使用模板时锁定版本；编辑模板生成用户副本或新版本，不直接修改历史任务。Agent 可以推荐或调用模板，但不直接修改模板内容；Agent 临时调整只保存为本次任务提示词。

### 19.6 三个工作区的联动边界

```text
图库 / 看图
  负责浏览、焦点和选择

Agent 批处理
  负责自然语言目标和多步骤批处理

AI 批量修图
  负责模板驱动的批量生成

提示词模板
  负责模板市场、版本和收藏
```

跨页面联动必须使用明确动作，例如“加入 Agent 批处理”“加入 AI 批量修图”“使用当前选择”和“同步当前选择”。切换侧边栏不会隐式重置或扩大任务范围。

### 19.7 首次使用和模型配置

如果没有启用视觉模型或生图模型，AI 面板不应只在点击后报错，而应在主按钮旁显示明确的配置状态：

- 未配置视觉模型：显示“配置视觉模型”，点击后直接打开设置中的模型页。
- 已配置视觉模型但未配置生图模型：允许先执行分析，并把主按钮显示为“分析完成，配置生图模型后生成”。
- 两类模型都可用：显示正常的“分析并生成”主按钮。

模型设置页只保留“视觉分析模型”和“图片生成模型”两个首要入口；超时、重试、自定义请求头、存储策略等放入“高级设置”。

### 19.8 交互收敛原则

- 同一任务只提供一个主动作，避免同时出现“加入工作流”“加入生成队列”“开始分析”等竞争按钮。
- Agent 批处理和 AI 批量修图是独立工作区，不是普通操作入口；普通用户通过图库和看图的选择操作进入它们。
- 任务状态是全局信息，标签页切换不能隐藏；底部展示批次简要进度，抽屉及任务中心按批次原地展开详情。
- 专业信息默认折叠，错误、权限和模型缺失等阻断信息必须直接显示并提供下一步操作。
- 高级选项的默认值必须足以完成一次合理处理，不要求用户先创建模板或修改规则。

### 19.9 分析语言与任务批次

- 所有分析、相册分析、生成、Agent、导出及后续任务类型统一按 `类型 + submissionId` 组织。每次提交创建独立、持久的批次身份；重试不改变批次。旧任务回退到 batchId 或任务 ID，不按时间猜测归组。
- 图片生成的 `batchId` 继续表示单张图的一组候选，用于独立提示词、数量调整等；`submissionId` 表示用户本次提交的所有图片和候选。两者不能混用。
- 分析的人类可读字段跟随提交时的程序语言（简体中文或英文），JSON 字段名、枚举、参数和 OCR 原文保持协议语义。切换界面语言不修改既有结果。
- 底部任务栏显示各批简要信息及独立进度条；展开后显示简要批次列表。任务中心按批次显示总数、成功、处理中、等待、失败、暂停及取消，失败筛选保留所在批次的完整上下文。
- 点击底部任一批次，在后台任务抽屉内展开该批次；任务中心同样使用可展开的分组列表，不新增标签页。旧任务详情标签迁移为任务中心。详情不夹带其他批次或无关文件操作历史。
- 批次展开后的图片项展示完整缩略图，单击缩略图或双击图片行打开页内看图，按 Esc 返回展开位置。任务按 Asset ID 独立读取图片，不受当前图库目录、筛选及分页影响；历史任务同样适用。图片已移除时不跳转到其他图片。
- 批次标题提供重试失败/取消项与删除整批按钮，右键菜单不重复这两个操作。批次菜单提供展开/收起、暂停、恢复、取消；图片项菜单提供看图、定位原图及按状态显示的单项控制和提示词编辑，不放置行内删除/重试按钮。
- 两级菜单的多范围删除统一收进默认折叠的“批量删除”分组：批次级为下面批次、所有任务、未完成任务；图片级为本批下面项、本批全部项、本批未完成项。图片级保留单项删除与重试，操作范围以实际显示顺序为准并覆盖尚未加载的成员。
- 删除活动任务或多项任务前确认数量；仅删除任务记录，保留原图、分析结果及生成文件。任务中心移除重复标题和统计行，将数量放进筛选标签，重试与清空放在同一行右侧。
- 详情包括图片、文件名、状态、对应本次分析结果及质量评分、生成结果与提示词、相册建议、Agent 执行结果或逐文件导出报告，并保留单项暂停、取消、重试及等待生成任务编辑。
- 分页不可截断批次成员，首页包含所有尚未结束的批次，查询补齐批次全部成员。分析结果保存本次快照，避免历史任务展示后来的分析。
- 进度按已结束项 / 总项计算，成功、失败和取消分别显示；不伪造模型内部进度。导出按实际文件数量计数并持续保存逐项结果；单次相册分析或 Agent 执行以其任务为单位。
