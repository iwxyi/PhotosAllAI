# 关联文件夹与照片文件管理交互设计

状态：设计基线（第一阶段实施中）  
日期：2026-09-25  
适用平台：macOS、Windows

## 1. 目标与术语

侧栏标题使用“关联文件夹”。它表示图库对用户现有磁盘目录的引用关系：添加文件夹只建立索引，不导入或复制原图；关联路径不可用时图库可离线，但本地评分、色标、标签、分析和生成记录仍保留在应用数据库中。

界面、快捷键、菜单和确认文案必须区分：

| 对象/操作 | 改变磁盘原文件 | 改变图库数据库 |
| --- | --- | --- |
| 关联/取消关联文件夹 | 否 | 是，建立或移除路径索引 |
| 移动/复制照片 | 是 | 是，更新路径/建立新 Asset |
| 从图库移除照片 | 否 | 是，软移除索引 |
| 移入系统回收站 | 是 | 是，软移除索引 |
| 星级、首选、色标、标签、AI 描述 | 否 | 是 |
| 相册 | 否 | 是，虚拟集合 |

评分、首选、色标和标签只写入本程序数据库。绝不能写 XMP、EXIF、文件扩展属性或原图；将来若支持元数据 sidecar，必须作为独立可选功能并默认关闭。

## 2. 交互模型

### 2.1 树与焦点

- 目录树是可键盘操作的树形控件，每行包含独立的展开按钮和目录选择/拖动区域；展开与选择不互相吞掉事件。
- 树获得焦点后，`↑/↓` 移动焦点，`←` 收起或移到父目录，`→` 展开或进入首个子目录，`Home/End` 到首/末可见项，`Enter` 打开目录图库视图，`Space` 选择当前行。
- 第一阶段目录树采用单选导航模型：焦点行也是当前浏览目录。文件夹批量选择会随目录重排/复制功能一并引入，避免在仅支持单目录浏览时制造无效的“多选目录”状态。
- 左键单击选择目录；右键菜单保留重命名、在图库显示、在文件管理器显示、同步、重新定位、颜色和取消关联。
- 目录颜色仅作用于对应树节点图标，不继承到子目录；颜色变化仅写本地偏好，不影响磁盘。
- 树节点保持稳定图标、名称与计数列。名称省略显示但完整路径/名称由悬浮提示提供，不能挤压图标或计数。

### 2.2 选择与图库一致性

- 网格、胶片带、目录切换、键盘焦点和批量选择使用同一 selection state。焦点照片是预览目标，选择集是批处理目标。
- 从网格或胶片带拖动已选照片时拖动整个选择集；若起拖项未选中，则只拖该项，不悄悄重置其余选择。
- 拖放结束后不因 dragstart/dragend 清空选择。键盘范围锚点在树与照片列表之间分别维护。
- `Ctrl/Cmd+A` 作用于当前视图结果；超过已加载窗口时明确提示选择范围，不能静默只选择虚拟列表已渲染项。

### 2.3 拖放意图

拖放目标在 hover 时显示清晰目标行和操作动词，拖动指针显示项目数量。每个拖放动作均有菜单/命令替代入口。

| 起点 → 目标 | 默认动作 | 修饰键/替代动作 |
| --- | --- | --- |
| 网格/胶片 → 关联文件夹 | 移动原文件 | 按住 `Ctrl` 复制；macOS 同时接受 Option 作为系统习惯 |
| 关联文件夹 → 关联文件夹 | 移动真实目录，并同步其中照片及便携生成版本路径；禁止拖入自身、后代或同名目标 | 根关联目录移入另一关联树后自动合并关联边界，避免形成重叠根；目录复制仍属于后续阶段 |
| 外部文件管理器 → 关联文件夹 | 移动进目标目录 | `Ctrl` 复制；发生跨卷时必须显示实际采用的复制-校验-删除流程 |
| 外部文件管理器 → 网格 | 关联/导入这些来源，不移动 | 用户明确从目录树目标行放下才执行磁盘移动/复制 |
| 网格/胶片 → 外部程序 | 提供真实原图文件 | macOS/Windows 原生文件拖放，不以应用内资源 ID 替代 |
| 网格 → 相册 | 加入虚拟相册 | 不移动文件；智能集合拒绝放入 |

拖动目标必须拒绝：离线/只读目标、把目录拖入自身或后代、重复目标、正在执行文件事务的资产、无效修饰键组合。无效拖放不得退化成“从图库移除”。

## 3. 文件操作安全规则

- Renderer 仅传稳定 Asset ID、Folder ID 和动作；任意本地路径只通过受限 IPC 进入 Main。Main 再解析路径、权限和目标关系。
- 照片移动/复制复用 `FileOperationService` 的持久事务、冲突避让、校验、补偿、恢复和撤销历史。拖放默认保留同名两份并自动编号，不覆盖。
- 移动到同一源目录、当前子目录或其内部目标均拒绝或作为明确 no-op；绝不通过“先移后索引”的独立 Renderer 逻辑操作文件。
- RAW/JPEG/XMP companion 默认不随照片拖动；拖放反馈标注未包含的伴随文件，并提供现有“移动到/复制到”对话框以显式选择 companion。目录递归复制则必须完整预览文件数/容量与排除项。
- 跨卷移动先复制、大小与 SHA-256 校验，再删除来源；任一步失败保持来源并报告。系统回收站失败不得伪报成功。
- 所有批量文件操作写入操作历史，成功移动可撤销。撤销前重新验证来源/目标没有后续变化。
- 文件监视器在操作完成后协调扫描目标和来源；外部变化不应导致照片、评分或生成关系重复创建。
- 评分/色标/收藏/标签等随 Asset ID 保存在本地数据库。文件移动或重命名不得丢失或外写这些数据。

## 4. 专业管理器能力范围

第一阶段提供图库内部拖放、树键盘导航、Ctrl 复制、错误提示和现有文件操作历史闭环。

后续按以下顺序扩展：

1. **系统拖入**：接收 Finder/Explorer 的 FileList，在目标行反馈移动/复制；通过 Electron preload 安全提取路径，由 Main 校验来源、目标、文件类型、权限和碰撞，使用同一操作事务；导入完成后刷新索引。
2. **系统拖出**：Renderer 发起受限的导出拖拽请求，Main 解析选中的 Asset ID 到实际原图路径，并使用 Electron `webContents.startDrag` 提供平台原生拖拽图标和文件路径。生成图采用单独命令，避免原图/派生图混淆。
3. **目录树组织**：支持同卷目录重排、受控复制目录、展开/收起全部、在系统文件管理器显示、断链重新定位、拖放取消反馈。跨卷目录移动采取预览+事务，不以普通 `rename` 处理。
4. **批量整理**：批量重命名预览（原名/拍摄时间/序号）、复制/移动冲突统一策略、标签与评分快捷键、相册拖放、最近目标与固定目标。
5. **进阶**：撤销/重做栈、可恢复操作队列、文件夹收藏与过滤器、外部目录变化对账报告、操作历史按时间/类型/状态过滤。

原生拖入/拖出在 macOS 与 Windows 分别做真实文件系统 E2E 验证后才能标记完成；Chromium DataTransfer 内部测试不能替代平台验收。

## 5. 键盘与可访问性

- 焦点样式必须可见，目录树用 `role="tree"` / `treeitem`、`aria-expanded`、`aria-selected` 与 roving tabindex 表达状态。
- 树选择数量、拖放动作和错误不能只用颜色表达；读屏可获取目标目录名称与移动/复制动作。
- 拖放始终有等价键盘路径：选照片后用菜单“移动到文件夹/复制到文件夹”，选择目标并确认。
- `Escape` 取消当前拖放/菜单/对话框，不执行任何操作。
- `Delete` 不做物理删除；删除必须从明确的上下文菜单中选“移到系统回收站”并确认。

## 6. 第一阶段验收

- 侧栏显示“关联文件夹”，首次导入和移除文案说明只建立/取消路径关联。
- 目录树可聚焦，方向键导航，Enter 打开当前目录，左右键展开/收起，键盘焦点不会改变星级/色标或磁盘文件。
- 从网格拖动多选照片到关联文件夹执行事务移动；按住 Ctrl 复制；起拖未选照片时只影响单张。
- 目录树中的真实文件夹可直接拖到另一目录；操作改变磁盘目录，保持 Asset 身份，并在失败时回滚。关联根移入另一关联树后，原根关联自动退出，避免重复索引。
- 不覆盖同名照片；操作后图库路径、计数、选中状态和文件操作历史一致。失败不会显示成功，来源文件仍可恢复。
- 图片管理元数据只更新数据库；磁盘原文件及 XMP 内容不变。
- 外部文件拖入/拖出未实现时不显示虚假的系统拖放 affordance，并在产品待办中保留。

## 7. 风险与验证

| 风险 | 防护/验证 |
| --- | --- |
| 拖放误移动 | 目标行高亮写明“移动/复制”，撤销历史可见，Ctrl 复制，冲突绝不覆盖 |
| Finder/Explorer 修饰键差异 | 平台约定映射独立测试；同时提供上下文菜单命令 |
| RAW 伴随文件遗漏 | 默认明确提示，提供显式 companion 对话框 |
| 数据库与磁盘路径分叉 | 统一主进程事务服务、监视器协调、恢复测试 |
| 外部程序拖出时路径/权限泄漏 | 只允许 Asset ID 白名单；Main 解析路径，不暴露通用 shell/文件系统 API |
| 大批量任务卡顿 | Main 批处理，Renderer 不逐项同步 IPC；进度及取消使用持久 operation ID |
| 外接盘离线或只读 | drop target 禁用并说明原因；不改变索引状态 |
