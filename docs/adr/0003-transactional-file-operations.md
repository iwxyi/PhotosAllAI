# ADR 0003：原图文件操作采用持久计划与补偿事务

- 状态：Accepted
- 日期：2026-09-18

## 背景

图库需要在 macOS 和 Windows 上移动、复制和重命名原图。文件系统不提供跨多个文件和 SQLite 的统一事务；跨卷移动还会让普通 `rename` 以 `EXDEV` 失败。批量操作中途失败、应用退出、重名或权限变化都可能让磁盘与目录索引不一致。

Renderer 也不能获得或提交任意本地路径，否则会破坏 Electron 的权限边界。

## 决策

移动命令只接受稳定的 `assetIds` 和已导入的 `targetFolderId`。主进程中的 `files` 服务按以下阶段执行：

1. 从目录数据库解析并验证源位置和目标目录。
2. 在任何文件副作用前持久化操作与逐项计划。
3. 预留整批目标文件名；冲突使用 `name (n).ext`，绝不覆盖。
4. 同卷使用不覆盖的硬链接原子发布，发布成功后删除源文件名。
5. 不支持硬链接或跨卷时，复制到目标目录内的临时文件并校验大小和 SHA-256；优先以不覆盖的硬链接原子发布，不支持时再用不覆盖复制发布并复验，最后删除源文件。
6. 全部文件成功后，在一个 SQLite 事务中更新 Asset 位置和操作状态。
7. 任一项失败时逆序补偿已完成项；启动时恢复未完成操作。

一个批次对目录数据库采用全有或全无语义。失败报告包含操作 ID 和是否完整回滚，但不向 Renderer 暴露真实路径。AI 生成版本属于受管存储，不随原图移动；它继续通过稳定 Asset ID 关联。

复制会产生真实独立文件和新的 Asset ID，继承评分、收藏和用户标签，但不复制 AI 分析或生成版本。重命名保留 Asset ID，并拒绝扩展名变化、平台非法名称、系统设备保留名和覆盖冲突；仅大小写变化时使用平台原生重命名。

“从图库移除”采用 Asset 软移除：原文件不变，图库查询和协议解析立即隐藏该资源，分析与生成版本继续关联原 Asset ID；再次扫描同一路径会恢复该 Asset。“移到系统回收站”逐项调用操作系统回收能力，每项成功后立即软移除；系统 API 不提供可靠程序化撤销，因此批量操作允许明确的部分成功，不承诺伪原子回滚。应用中断后根据源路径是否仍存在完成目录对账。

Renderer 可读取不含真实路径的操作摘要；完整源路径和目标路径仅保存在本机 SQLite 事务日志中。

## 结果

- 重名文件、跨卷移动和批次中途失败不会静默覆盖或造成已知的部分提交。
- 操作日志可用于启动恢复和后续诊断。
- 跨卷移动需要完整读取两次内容，速度低于直接重命名，但换取了删除源文件前的内容验证。
- 极端情况下补偿本身也可能因介质离线或权限变化失败；此时保留 `compensation_failed` 状态和操作 ID，不伪报成功。
