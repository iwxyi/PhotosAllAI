# 实施与验收计划

> 原则：每个里程碑交付可运行的垂直切片，完成自动化验证和 Git 提交后才进入下一阶段。

## 1. 完成定义

每项功能只有同时满足以下条件才算完成：

- 产品行为与数据边界已写入文档或 ADR。
- 正常、空、加载、失败、离线和恢复状态已实现。
- 领域逻辑、契约和关键交互具有相称的自动化测试。
- 不产生新的高严重度安全或数据丢失风险。
- 通过 lint、类型检查、单元测试、构建和适用的端到端测试。
- 在目标平台完成视觉与性能抽查。
- 变更以范围清楚的 Git commit 保存。

## 2. 里程碑

### 当前实现基线（2026-09-19）

已落地并持续回归的能力包括：

- M0 工程基线、Electron 安全边界、跨平台构建与 CI。
- M1 文件夹导入、分页/虚拟缩略图、缓存预览、RAW 原生/代理预览（macOS sips、可选 ImageMagick）和会话恢复。
- M2 目录、相册、智能集合、标签管理、评分收藏、搜索、排序、多选和事务文件操作。
- M2.1 离线文件夹显示离线数量，并可选择新位置重新关联；优先按相对路径保留 Asset ID，改名或目录重组后可通过唯一的大小/修改时间指纹保守匹配，同时同步便携生成结果路径；指纹冲突时不会猜测身份。
- M2.2 批量复制在写入前按总字节预检目标卷空间，跨卷移动仅计算需要复制的数据；容量不足时不创建操作日志、不修改文件或图库。
- M2.3 Windows 文件操作在规划阶段校验目标与临时文件的完整路径长度，超过兼容上限时在写入和落库前失败。
- M3 Provider 配置、连接测试、结构化视觉分析和批量分析入队。
- M3.1 Provider 配置支持删除，并同步移除本地密文凭据；被运行中或等待中任务引用时拒绝删除，历史任务仍保留原 Provider ID 用于追溯。
- M4 模板版本、示例预览、串行生成队列、重排、取消、重试、结果审阅和任务中心。
- M4.1 等待中的生成任务可编辑最终提示词；更新仅允许发生在 `queued` 状态，并写入任务事件审计，开始执行后拒绝修改。
- M4.3 等待中的同照片生成批次可原子切换已启用的生成 Provider、模板快照和最终提示词，并可在 1–20 次间增减生成数量；新增任务使用新序号，已开始任务保持不可变。
- M4.2 模板支持归档而非物理删除；归档后不再出现在新任务列表，历史版本和生成记录继续保留用于追溯。
- M5 原图/生成图比较、版本切换、导出预设、批量导出、诊断摘要，以及集中受管/原图旁便携两种生成结果存储策略。
- M5 原图和生成版本均可通过稳定 ID 在 Finder/资源管理器中定位，Renderer 不接收真实文件路径。
- M5.1 图库数据库一致性快照：通过 SQLite `VACUUM INTO` 导出，不复制活动 WAL 文件，设置页可保存并校验 SHA-256；不包含 API Key。
- M5.2 启动后每日创建一次数据库一致性快照，默认保留最近 7 份；自动备份失败不会阻断启动。生成结果文件仍需单独备份或导出。
- M5.3 可复制或导出经过 Schema 白名单约束的诊断摘要；JSON 文件包含生成时间和 SHA-256，并由端到端泄漏扫描确认不包含路径、密钥、图片、提示词或模型响应。
- M5.4 导出预设支持保留原格式，或转换为 JPEG/PNG；可配置 JPEG 质量和长边限制，批次中的转换失败会记录到报告而不阻断其他文件。
- M5.5 完整图库备份包含一致性数据库快照、快照中引用的集中受管生成结果及逐文件 SHA-256 清单；临时目录校验完成后原子发布，不复制原图、凭据或原图旁便携结果。
- M5.6 设置页可独立验证完整图库备份的严格清单、SQLite 完整性、受管结果引用、文件大小和 SHA-256；路径逃逸、重复清单项、缺失或篡改文件均拒绝通过。
- M5.7 Schema 升级前创建一致性数据库 checkpoint，所有服务迁移成功后才提交版本；中断后下次启动先验证并恢复旧库，保留失败数据库，高版本图库拒绝降级打开。
- M5.8 原图内容哈希在后台空闲时小批量索引，AI 任务活跃时暂停；文件元数据变化后自动失效。文件夹重新定位在相对路径和唯一元数据匹配后，可用唯一 SHA-256 解决同尺寸同时间但内容不同的歧义，重复内容仍不猜测身份。
- M5.9 完整图库恢复采用验证暂存、重启前再次验证、启动期原子目录切换三阶段；只复制清单白名单，重写受管结果路径，旧图库作为恢复前副本保留，验证或切换失败不覆盖可用原图库。
- M5.10 移动或复制照片前识别同目录同名主体的 RAW+JPEG 与 XMP；对话框显示关联文件和额外体积且默认不勾选，用户启用后关联文件进入同一个空间预检、冲突避让、哈希校验、持久日志与失败补偿事务。
- M5.11 预览缓存默认限制为 5 GiB，可在设置中选择 1–50 GiB；修改后立即按最近使用时间淘汰，运行期间生成新预览会延迟复查预算，清理失败不虚报释放空间且不触碰持久内容。
- M5.12 已完成且未被后续路径操作取代的移动、重命名可从任务中心撤销；关联文件逆序恢复，冲突与空间在写入前检查，中途失败前推补偿，`undoing` 日志可在重启后完成恢复，便携生成结果同步回迁。
- M5.13 源文件夹可从图库注销而不触碰磁盘文件；文件夹及其 Asset 使用软移除保留稳定身份、评分、标签、相册、分析与生成版本，重新导入同一路径后恢复。存在活动 AI 任务或文件事务时拒绝注销，目录监视器只跟踪活动根目录。
- M5.14 侧栏“最近 30 天”使用实际导入时间动态计数和筛选；图库摘要显示真实活动文件夹与照片数量，移除会误导真实工作流的硬编码容量和计数。
- M5.15 工作区会话 v2 恢复相册、智能集合、标签、仅首选筛选、排序、搜索和选中照片；旧 v1 会话读取时安全迁移，未知或损坏版本仍回退默认状态。
- M5.16 大图工具栏支持单张收藏切换并暴露可访问按下状态，多选操作栏支持整组选区收藏或取消收藏；操作后同步刷新首选集合计数和当前筛选结果。
- M5.17 生成版本删除进入应用内部回收站并可冲突安全地恢复；活动列表、智能集合、导出、批次清单和完整备份排除回收版本，跨卷移动完成大小与 SHA-256 校验后才删除源文件，版本序号永久不复用。
- M5.18 设置页显示生成版本回收站数量、占用和异常状态，并提供二次确认的永久清理；主进程只删除严格受管路径中的普通文件，越界路径与符号链接保护性跳过，采用隔离改名、删除文件、删除记录的可恢复顺序并报告部分失败。
- M5.19 脱敏诊断包含图库存储完整性结果：SQLite 快速检查、活动与回收版本缺失、受管路径逃逸、非普通文件、不可访问项及未登记载荷。界面支持重新检查，报告只输出计数和状态；内容级 SHA-256 仍由完整备份验证负责。
- M5.20 永久清理生成版本采用数据库持久化意图、同目录确定性隔离、载荷删除、记录删除四阶段协议；启动和手动重试可幂等恢复任一中断点。旧版单一 UUID 隔离文件可安全收敛，双文件冲突、多个候选、符号链接、未知文件及越界路径一律保留并报告。
- M5.21 导入目录监视器合并文件事件但不丢弃协调期间的新事件；监听错误会立即触发离线协调，并以受控间隔重新建立监听。可移动磁盘或网络目录恢复后自动重新扫描，目录集合更新时保留未变化的监听器。
- M5.22 真实素材验收遍历所有修改时间、文件名和评分排序分页，核对受支持格式直方图、稳定 ID 唯一性及测试前后逐文件元数据；文件名排序的游标比较与 `NOCASE` 排序统一，避免大小写混合图库跨页重复或遗漏。
- M5.23 图库导入在文件遍历和元数据读取期间不持有 SQLite 写锁，按最多 256 项的短事务提交，使评分、标签、AI 队列等并发写入保持可用；重复导入返回零新增，协调扫描按路径准确报告同时增删场景。
- M5.24 预览缓存键同时包含 Asset ID、源文件修改时间和字节数，避免保留时间戳的替换文件命中旧预览；缓存命中和发布竞争只接受普通文件，原子发布所有失败路径清理临时载荷，启动时仅清理严格命名的普通缓存临时文件。
- M5.25 生成结果在落盘前持久化写入意图，成功写入文件、记录和 manifest 后才清除；启动先恢复文件事务并迁移便携意图，再回滚未完成生成写入并刷新 manifest。路径须按 Asset、批次和存储策略重新计算，符号链接、越界或不匹配条目保持不动并报告。
- M5.26 脱敏完整性诊断识别生成写入意图：短期正常写入的受管载荷不误报为孤立文件，超过五分钟的意图产生警告，无法按当前 Asset、批次和存储策略验证的路径产生错误；设置页与导出报告只显示计数。
- M5.27 完整图库备份会从一致性快照中移除未完成生成写入意图及其临时结果记录，避免恢复旧机器绝对路径或半完成载荷；诊断和启动恢复逐层验证生成目录，不跟随中间层符号链接。
- M5.28 脱敏诊断保留本次启动的回收站清理、文件事务和生成写入恢复计数，设置页可见恢复、冲突与失败数量，不包含路径、文件名、提示词或图片内容。
- M5.29 真实预览验收在隔离副本上驱动打包 Electron 解码八张大体积相机图片，验证尺寸、跨重启磁盘缓存命中和原素材只读性，并输出冷/热耗时供固定硬件基线使用。
- M5.30 Provider 分析与生成响应采用独立超时和流式字节上限；远端生成图片先解析并拒绝任一私网地址，再将连接固定到已验证公网 IP，避免 DNS 重绑定。DNS 解析、下载流、任务取消和无 `Content-Length` 超限响应均有自动化覆盖。
- M5.31 诊断导出只覆盖普通文件，并通过同目录临时文件与旧文件暂存进行可回滚替换；发布失败时恢复原内容，符号链接和目录目标不会被跟随或覆盖。
- M5.32 应用设置、Provider 配置、生成批次 manifest、手动与自动数据库备份共用跨平台可回滚文件替换协议；Windows 不依赖覆盖式 `rename`，暂存或 SQLite 快照生成失败会清理临时文件，manifest 发布失败保留上一有效版本。
- M5.33 数据库迁移 checkpoint 与 Schema 版本状态使用同一可回滚文件替换协议；固定临时名和符号链接目标均被消除，失败提交保留待恢复 checkpoint。
- M5.34 完整图库备份在内容构建完成后才分配发布名称；同一时间戳的并发备份遇到名称竞争会保留双方并自动编号，两份清单均需独立通过完整校验。
- M5.35 启动自动数据库备份在诊断摘要中暴露脱敏会话状态（进行中、已完成、已跳过或失败），失败不会阻断启动，也不会泄漏路径或错误详情。
- M5.36 目录监视器暴露脱敏健康计数：活动目录、活动监听器、监听失败和协调失败；单次监听或协调失败不会终止后续重连与扫描。
- M5.37 文件操作错误在 Renderer 统一使用稳定的用户文案映射；未知错误和包含本地路径的异常文本不会回显，原始错误码仅保留在主进程历史记录中。
- M5.38 同一应用进程内的自动数据库备份按串行队列评估最小间隔和保留策略，避免并发启动或手动触发造成重复快照或时间戳文件竞争。
- M5.39 跨应用进程的自动数据库备份使用同目录独占锁协调；锁带有进程所有者、创建时间和随机所有权令牌，释放前验证令牌，死进程遗留锁通过原子改名隔离后回收，锁元数据写入失败会立即清理并失败，不会留下无主锁。

当前明确未完成或仅有受限实现的项目：完整 LibRaw/Rust 显影链路、多 GPU 预览和正式签名/公证。RAW 仍使用系统预览、macOS sips 或 ImageMagick 代理，不应替代完整显影验收。界面现已支持深色、浅色和跟随系统主题。

### M0：设计和工程基线

交付：

- 产品设计、系统架构、质量安全规范和 ADR。
- Git、pnpm workspace、统一脚本、lint、格式化和测试框架。
- Electron 安全窗口、React Shell、设计令牌和组件展示页。
- CI 可执行的类型检查、测试和构建。

验收：开发模式和打包构建均可启动；Renderer 无 Node 全局能力；基础测试全部通过。

### M1：图库浏览垂直切片

交付：

- 创建或打开图库。
- 添加本地文件夹、扫描支持格式、分页展示。
- 目录树、虚拟化缩略图、焦点与多选。
- 大图预览、预取、缓存和错误占位。
- SQLite 迁移和可恢复的资源定位。

验收：10,000 条模拟资源下可交互；真实 JPEG/PNG/HEIC 样本可浏览；重启状态保持。

### M2：工作区与文件管理

交付：

- 工作区级多标签、会话恢复和 Command Registry。
- 文件夹、相册、智能集合基础能力。
- 移动、复制、重命名、回收站、冲突处理和文件事务日志。
- 标签、评分、收藏、筛选和 FTS 搜索。

验收：同卷、跨卷、冲突、权限失败和进程中断场景通过恢复测试。

### M3：AI 分析

交付：

- Provider Profile、系统凭据库和连接测试。
- OpenAI Compatible 视觉分析适配器。
- 快速编目、完整分析和批量分析。
- 统一分析 Schema、版本化、AI 标签和动作审核。

验收：使用模拟服务完成确定性契约测试；真实自带配置通过人工冒烟，不把秘密写入日志。

### M4：模板、生成和队列

交付：

- 模板库、版本、示例图和变量解析。
- NanoBanana Compatible 生成适配器。
- 生成方案、批次、多次生成和持久队列。
- 排序、批量编辑、取消、重试、崩溃恢复和任务中心。
- 受管结果存储、manifest 和回收站。

验收：模拟超时、限流、损坏响应、磁盘不足和崩溃后不会丢失已完成结果或重复记账。

### M5：版本比较与导出

交付：

- 原图/版本快速切换、同步左右比较和滑杆比较。
- 首选、接受、拒绝和批量重新生成。
- 导出预设、命名预览、格式选项和结果报告。
- 集中受管与原图旁便携存储策略，任务和 manifest 记录实际策略，支持后续导出；原图移动/重命名后便携结果可重定位。

验收：不同尺寸、方向和色彩配置的比较正确；导出冲突和部分失败可恢复。

### M6：RAW、性能和发布候选

交付：

- Rust sidecar、RAW 内嵌预览和完整解码。
- 缓存治理、性能模式、内存与 GPU 资源回收。
- 安装、升级、迁移、签名和诊断包。
- macOS/Windows 发布候选。

验收：性能数据达到产品设计目标或有经批准的差异记录；升级和卸载不删除用户图库。

## 3. 验证矩阵

每个里程碑按以下层次验证：

| 层次 | 内容 |
| --- | --- |
| 静态 | TypeScript strict、lint、依赖与许可证检查 |
| 单元 | 领域状态机、命名、选择模型、模板解析 |
| 契约 | IPC Schema、Provider 模拟服务、sidecar 协议 |
| 集成 | SQLite、文件事务、恢复、缓存和凭据引用 |
| 组件 | 所有状态、键盘行为、长文本和无障碍 |
| E2E | 导入、分析、生成、比较、重试和导出闭环 |
| 视觉 | macOS/Windows、深浅主题、多 DPI 截图回归 |
| 性能 | 大图库、RAW、快速切图、后台队列和内存 |
| 故障 | 断网、限流、磁盘满、权限、崩溃和损坏文件 |

本地真实素材可放在不受 Git 管理的 `test_data/`，运行 `pnpm test:real-data` 执行只读全量扫描验收。测试会核对可导入格式数量，完整遍历三种排序分页，并在前后比较每个源文件的路径、大小和修改时间；数据库只写入系统临时目录，常规 CI 不依赖私有素材。

运行 `pnpm test:real-data:preview` 会从真实素材中选择体积最大的八张受支持图片，复制到隔离临时目录后通过打包 Electron 执行冷/热预览解码。测试验证输出尺寸、缓存复用并打印当前硬件耗时；原素材仍只读并在结束后复核大小和修改时间。耗时先作为硬件基线记录，建立固定发布硬件档位后再启用回退阈值。

## 4. Git 策略

- `main` 始终保持可构建。
- 当前由单一开发代理推进，采用短生命周期提交而不是长期分支。
- 提交使用 Conventional Commits：`feat`, `fix`, `docs`, `test`, `refactor`, `build`, `chore`。
- 每个里程碑至少建立一个可识别基线提交。
- 不提交秘密、用户图片、运行数据库、缓存和构建产物。
- 数据库迁移只追加不改写；已发布迁移禁止重排。

## 5. 风险优先验证

优先建立技术探针验证：

1. Electron 大图预览、虚拟列表和内存回收。
2. RAW 内嵌预览在常见相机格式上的覆盖率。
3. OpenAI/NanoBanana 兼容接口的差异范围。
4. Windows 路径、文件锁、回收站和跨卷移动。
5. 色彩管理与预览/导出一致性。
6. 生成服务返回 URL 时的安全下载。
