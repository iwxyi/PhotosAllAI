# 大量图片浏览与批量生成路线图

> 代码核对：2026-11-03。本文是当前产品范围、能力状态、后续 TODO 和验证点的入口。“已有”只表示代码路径存在，不等于真实设备上的性能或发行认证。

## 定位与取舍

**核心任务：大量图片快速浏览与选片；从当前选择创建图片批任务，比较候选、选优并交付。** 速度与连续操作手感优先于功能数量。AI 与 Agent 为完成任务服务，未配置模型时看图和整理仍可用。后续可以加入轻量视频浏览与简单剪辑，但不做网页素材采集、完整多轨剪辑或 Lightroom 级 RAW 调色。

参考 Eagle 的高频预览、快速筛选、低摩擦操作；参考 Lightroom Classic 的选片、旗标/评分、比较和分级预览。参考产品的功能或宣传数字不是本程序的验收结果。

### P0：先量化，再消除前台阻塞

- [ ] **建立可复现基线。** 固定 1 万、10 万张混合 JPEG/HEIC/RAW 资料集，并含深目录、长文件名、外置盘和少量损坏文件。采集启动到可操作、临时打开目标图、首屏缩略图、连续切图、滚动帧耗时、输入延迟、内存与磁盘/CPU 使用。分别记录冷/热缓存，以及后台生成运行中状态。现有万张分页测试只证明查询遍历，不代表真实图像浏览。
- [ ] **图库统一窗口化。** 网格、瀑布流、分组和列表仅挂载视口附近图片；保留框选、跨页 Shift 选择、键盘定位、分组标题、滚动锚点及 Esc 返回。验收：10 万张连续滚动后 DOM 数量和内存不随浏览页数线性增长；无持续白屏或选择错位。

### P1：把选片和批次结果做成连续工作流

- [ ] **连续选片。** 单键评分/旗标/色标、下一张自动推进、拒绝/保留过滤、全屏与胶片带状态记忆；输入框焦点不触发单键命令。验收：从 100 张照片选 20 张，鼠标和键盘均能无中断完成；返回网格仍定位原位置与选择。
- [ ] **比较与候选审阅。** 任意两张照片及原图/生成版本并排或滑杆比较，支持同步缩放与平移；在批次结果中用键盘接受、拒绝、设首选和跳到下一个未审阅项。验收：不同尺寸和方向不出现错位或错误像素倍率，修改审阅状态后计数立即一致。
- [ ] **批次结果工作台。** 以每张原图为单位展示候选、提示词和状态；提供未审阅、失败、首选筛选、局部重试与按首选导出。区分技术失败的重试与不满意的再生成。验收：一批 30 张、每张多个候选，从提交到选优导出不必返回全图库查找结果；部分失败可继续交付成功项。
- [ ] **保存复合筛选与来源状态。** 保存目录、格式、日期、评分、旗标、颜色、审阅状态等条件及排序；明确“当前视图全选”和“全部结果”。验收：重启、切换目录和进入看图后条件与选择范围不混淆。
- [ ] **相似与重复组人工复核。** 先交付展示依据、并排确认、保留/排除和撤销，不自动删除原图。验收：连拍和重复文件能解释分组原因；误判可恢复，不影响原图。

### P1：批任务吞吐与故障恢复

- [ ] **任务资源池与公平调度。** 在前台浏览预算内，将分析、生成、导出与解码分配独立有界并发；按 Provider 限流与 429 退避，避免长批次饿死短任务。验收：多批并行时进度、取消和暂停不串批，前台交互预算不被挤占。并发数以设备和服务商实测决定。
- [ ] **生成与导出幂等核对。** 对“远端已完成、本地收包前断开”、结果文件已落盘但数据库未提交、导出发布一半、重启重排队等场景加入稳定请求身份和恢复检查。验收：故障注入后没有无提示的重复付费生成、重复文件、丢失候选或伪成功；无法确定远端状态时明确显示待核对。
- [ ] **长时稳定性。** 10 万张图库持续浏览、反复切图、窗口缩放、外置盘断开/重连、磁盘满与批次运行中退出。验收：内存有界、数据库与文件可恢复、错误可复制，重开后选择与任务状态一致。

## 2026-11-04：退出崩溃的最小复现与修正

此前根据 `node::sqlite::UserDefinedFunction::xDestroy` 邻近符号推断 SQLite 导致退出崩溃，证据不足；上文相关归因和 `process.exit(0)` 已解决问题的说法在此撤回。仅凭 stripped binary 的符号名称不能定位调用源。

独立 Electron 37.10.3 程序提交 32 个 `nativeImage.createThumbnailFromPath` 请求后立即 `app.quit()`：有效图片 PID 3340、损坏图片 PID 3337 均以 SIGSEGV 退出。对应系统报告 `Electron-2026-11-04-013201.000.ips`、`013201.ips` 的栈顶为 `v8::api_internal::DisposeGlobal`，与原报告一致。JS `exit` 事件甚至记录 code 0，操作系统最终仍收到 SIGSEGV，测试必须核对子进程信号。

同批对照中，等待全部缩略图 Promise 后退出的空文件、损坏图片、有效图片各 32 请求均 code 0；无缩略图与仅执行 SQLite 操作也正常。崩溃组没有创建数据库或执行 SQLite 查询，但首版 fixture 顶层加载过 SQLite 模块，不能宣称完全排除模块初始化影响。移除该顶层加载后的重复实验卡在 ready 前，不能计入因果对照。

已证实的触发条件是 Quick Look 请求未完成时进入 Electron 退出清理。Electron v37.10.3 的 `shell/common/api/electron_api_native_image_mac.mm` 将持有 V8 Promise 的回调交给 Quick Look，再投递到主线程；崩溃表现为该回调生命周期与 V8 teardown 重叠。应用原关闭流程没有排空 ImageCacheService，是触发竞态的应用侧缺口；精确原生销毁位置仍需符号化确认。

修复：关闭预览队列时拒绝排队和新任务，等待活跃解码；图片缓存停止定时清理并排空解码；关闭期间图片协议返回 503；停机等待包含图片缓存，正常路径恢复 `app.quit()`。紧急超时仍可能中断原生请求，后续需解码进程隔离，不能宣称所有退出风险均已消除。

2026-11-07 普通瀑布流窗口化：按列记录卡片像素位置，视口滚动时二分定位每列首个可见卡片，仅挂载视口及上下缓冲区；键盘移动到未挂载照片时按位置滚动。`PHOTOALLISAI_PERF_COUNT=1000 PHOTOALLISAI_PERF_VIEW=masonry pnpm exec playwright test tests/e2e/catalog-real-media-perf.spec.ts --reporter=line` 在当前 macOS GUI 环境通过，滚动时挂载 43 张卡片，帧间隔 p95 9.7 毫秒，末端跳转与键盘回退通过，Tab 工作集约 456 MiB。此前未窗口化同内容样本挂载 1,000 张、p95 41.7 毫秒、Tab 工作集约 834 MiB；两者均为单轮同盘同内容 JPEG，不能外推为稳定收益。分组瀑布流仍未窗口化；大规模真实混合素材、缩放和长时内存仍待验证。
